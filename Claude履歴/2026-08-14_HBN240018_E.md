### 1. A-9 番兵 `-1` の決着（廃止）

E-1 着手時に判断する約束だった件。元コードを読み直したところ、
`tractmp(0) = -1` は `tractmp(k+1) = jtmp` と 1 つずらして詰めているだけで、
バックトレース側は `tracred(i,k)` を **k = 1 から**読む（元コード 903 行）。
つまり添字 0 は**一度も参照されない固定長配列のパディング**。

Python は可変長リストなので持つ意味がなく、`mesh[history[0]]` が -1 で最後の面を指す
事故のもとになるため**落とした**。これで **反射回数 = `len(history)`**。

### 2. E-1 `loop_noredundancy.py` の全面書き直し（虚音源バックトレース）

下書き段階だったものを、元コード 876〜1134 行に沿って書き直した。

出力は `PulseList` クラス。元コードの 11 列（反射回数・到来時刻・到来方向・6バンドエネルギー）
と同じ内容だが、**到来方向を単位ベクトルにして距離を別に持つ**ようにした。
元コードの `-vtgt` は正規化されておらず長さが経路長そのもので、
「方向」と「距離」が 1 列に混ざっていたため。分けておくと出力⑤（伝搬方向の可視化）に
そのまま使える。`direction * distance` が元の値に一致する。

#### ★元コードから意図的に変えた点：鏡像の式の `abs()`

元コード 911 行は面までの距離に `abs()` を掛けている。

```
temp = |n・p + d| / |n|   →   isrc(k) = isrc(k-1) - 2 * temp * n
```

鏡像の正しい式は符号付き `p - 2 (n・p + d)/|n|^2 * n` で、両者が一致するのは
p が面の**表側**にあるときだけ。裏側の虚音源に abs() を使うと、面を跨いで鏡像を作るかわりに
**面から遠ざかる方向へ動いてしまう**。凸な部屋なら実害は出にくいが、
凹んだ形状や法線を反転させたモデルでは崩れる。符号付きで実装した。

#### 検証（test.dxf = 2×3×1 m 直方体、解析解と突き合わせ）

| 項目 | 結果 |
|---|---|
| 直接音の距離 | **誤差 0.000e+00** |
| 1 次反射 6 本（6 面ぶんちょうど） | 全て**誤差 0.000e+00** |
| 2 次反射 18 本 | 全て虚音源の解析距離と一致 |
| 到来方向 | 受音点→音源の単位ベクトルと一致 |
| エネルギー | 入射角と吸音率から手計算した \|R(θ)\|² と**誤差 0.000e+00** |

音線法が拾った経路 972 本のうち 582 本が生き残り 390 本が却下された。
受音球の許容ぶんだけ偽の経路が混ざるので、これは想定どおりの動き。

### 3. E-3〜E-7 `impulse.py` の全面書き直し

転記ミスが 9 箇所あった。

| 箇所 | 旧 | 正 |
|---|---|---|
| ハミング窓 | `0.54 * 0.46 * cos(...)` | `0.54 + 0.46 * cos(...)` |
| 伝達関数の重ね合わせ | `transfer = transfer * ...`（積） | `+=`（和）。**積だと初期値 0 に掛かって全部 0 になる** |

| バンド端 | `(mf*2)^(-1/6)`、指数に fmax が混入 | `mf * 2^(∓1/6) / fmax` |
| 負周波数の添字 | `transfer[j, nn-i+1]` | 0 始まりでは `hfp[nn - i]` |
| フィルタのタップ添字 | `n_shift = i - 1.0 - m`（1 始まり前提） | `k - m` |
| 逆 FFT | 呼ばずに合算していた | `np.fft.ifft` してから実部を合算 |
| `df` | 引数に無く未定義参照 | 引数化（E-4） |

#### E-7 バンド数の不整合 → 6 バンドに確定

`procedure.py` が 63〜8000 Hz の 8 バンドを定義していたが、吸音率もバックトレースも 6 バンド。
**元コード make_ipls の 6→32 展開表（94〜125 行）から、6 バンドの中心周波数が
125/250/500/1k/2k/4k Hz と確定できる**（32 バンド側の 10 番目 = 125 Hz が
`enerred(1)` を参照している）。ipls2rt の `fc(i) = 125 * 2^(i-1)` とも一致。

#### E-6 の判断

- **FFT は `np.fft` に置き換えた。** 自作版は `m = 0` 始まりでゼロ除算になるなど動かない状態だった。
  `fft(x,n,1)` = `np.fft.fft`、`fft(x,n,-1)` = `np.fft.ifft`（符号と 1/n 正規化が一致）。
- **バンドパスは自作のまま残した。** `scipy.signal.firwin(..., scale=False)` と
  **相対誤差 1e-16 で一致**することを確認。一致するなら依存を増やす理由がなく、
  元コードとの対応が見えるほうがよい。
  （scipy は既定で通過域ゲインを正規化する `scale=True` なので、置き換えるなら注意）

#### バンドパスの遅れ（要注意）

元コードのバンドパスは**タップ数 = データ点数 nn** の直線位相 FIR なので、
出力は (nn-1)/2 サンプル ≒ **1.49 秒**遅れる。元コードは補正していないので、
出てくる CSV は「1.49 秒あたりから音が始まる」形になる。
`compensate_filter_delay=True` で巻き戻せるようにした。

### 4. E-8 残響時間 → `reverberation.py` を新設

元コード `ipls2rt_fortran.f90` の移植。Schroeder 積分 → 減衰曲線 → T30。

#### ★元コードから意図的に変えた点：巡回畳み込み → 線形畳み込み

**ここが今日いちばん時間を使ったところ。**

最初は元コードどおり FFT の掛け算（＝巡回畳み込み）で実装したが、
減衰率が既知の合成応答で検証したら **T30 が理論値の 5〜19 倍**になるか、そもそも算出できなかった。

切り分けた結果:

1. 素の Schroeder 積分は正しい（T60 = 0.4988 s / 理論 0.5）
2. フィルタ自体も正しい（通過域ゲイン 1.0、32 バンドの総和も平坦）
3. **フィルタ後の信号の末尾数サンプルにピーク級の値が乗っていた**

原因は、バンドパスが左右対称な直線位相 FIR なので入力の立ち上がりより**前の時刻**から
応答が始まり（プリリンギング）、巡回畳み込みではそれが**バッファ末尾に回り込む**こと。
しかもタップ数 = nn なので回り込みはバッファの半分に及ぶ。
結果、減衰曲線に -20 dB 程度の**床**ができて -35 dB まで落ちなくなっていた。

| 方式 | T60 = 0.3 s | 0.5 s | 1.0 s |
|---|---|---|---|
| 巡回畳み込み（元コード, タップ数 = nn） | 算出不可 or 5.89 s | 算出不可 or 5.85 s | 5.77 s |
| **線形畳み込み（4096 タップ）** | **0.29〜0.34 s** | **0.48〜0.52 s** | **0.98〜1.02 s** |

線形畳み込み（ゼロ詰めして畳み込み、遅れぶんを切り落とす）に変え、タップ数も既定 4096 にした。
**誤差の中央値 1.2 %**。125 Hz で減衰が短いときだけ 14 % 程度になるが、
これは帯域幅×減衰時間（BT 積）が小さいことによる手法の限界で ISO 3382 でも既知。

同じ理由で `impulse.py` の遅れ補正でも、巻き戻したあとに回り込み部分を切り落とすようにした。

#### 曲率（curvature）を足した

評価区間を半分にした推定値との食い違いを % で返す（ISO 3382 の C）。
0 に近ければ減衰が直線、**10 % を超えたら疑う**。
`nref` 不足で後部残響が切れているときの検知に使える。

比較相手は Paris の式で乱入射化した α_st = 0.669 を使う。

| | T60 |
|---|---|
| Eyring 式 | 0.0397 s |
| Sabine 式 | 0.0657 s |
