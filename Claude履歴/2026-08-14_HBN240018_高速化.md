## 1. F-1 高速化（NumPy ベクトル化）

### 何が遅かったか

元コードは「音線 1 本ずつ × 面 1 枚ずつ」の二重ループ。これをそのまま Python に写したので、
**音線 n 本 × 反射 k 回 × 面 m 枚**ぶん Python のループが回っていた。
ループ 1 回あたりの手間（関数呼び出しと小さい numpy 配列の演算）が大きすぎて、
実用的な規模ではまったく終わらなかった
（音線 3000 本・反射 8 回・面 1200 枚が 20 分たっても終わらない状態）。

### やったこと

**`mesh_method.FaceArrays`** に面をまとめ、**音線の束 × 全面**の交差判定を
1 回の配列演算で行う形にした。

- `loop_reflectionmesh.loop` … 音線ごとの Python ループを廃止。
  反射回数ループの中で「生きている音線」を配列でまとめて進める。
  反射履歴も元コードの固定長配列 `tractmp` と同じ持ち方（`(n_ray, nref+1)` の配列）にした
- `receiver_sphere.inside_sphere_batch` … 受音判定も束で
- `loop_noredundancy` … バックトレースの壁面探索も `FaceArrays` を使う

実装の要点:

- `denominator < 0`（表側から向かっている）と `t > 0` で候補を絞ったあと、
  **`np.nonzero` で (音線, 面) の組を 1 次元に潰してから**内部判定する。
  `(音線, 面, 3)` の 3 次元配列を作らずに済むのでメモリが小さい
- 最寄り面の選択は `np.lexsort((距離, 音線))` + 先頭抽出。
  lexsort は安定なので距離が同じなら面インデックスの小さいほうが残り、
  scalar 版が `distance_j < min_distance`（狭義）で先勝ちにしているのと**同じ結果**になる
- (音線 × 面) の要素数が大きくなりすぎないよう音線側を自動で分割する

**処理の順序（受音判定 → 打ち切り → 壁 ID 追記 → 反射）は元コードのまま。**

## 2. 残響指標を EDT / T20 / T30 に

60 dB 減を厳密に見ることは実務でほとんど無いというご指摘を受けて、
`reverberation.decay_measures()` が **3 つまとめて返す**形にした。

| 指標 | 評価区間 | 性質 |
|---|---|---|
| **EDT** | 0 〜 -10 dB | 初期減衰時間。**聴感上の響きの短さに近い**。初期反射の密度を反映する |
| **T20** | -5 〜 -25 dB | 暗騒音が高い実測でも取りやすい |
| **T30** | -5 〜 -35 dB | 最も一般的（ISO 3382 の標準）。元コードもこれ |

減衰曲線は 1 回だけ作って評価区間を変えて読み取るので、3 回別々に計算するより速い。
`measures` 引数に `{名前: (開始dB, 終了dB)}` を渡せば区間を変えられる。

出力例（test.dxf）:

```
     周波数       EDT       T20       T30        曲率
     63Hz     0.219     0.109     0.088      -24% ★
    125Hz     0.155     0.131     0.150      +12% ★
   1000Hz     0.125     0.112     0.104      -12% ★
```

## 3. 曲率の警告メッセージを直した

`nref` を 40 → 250 に増やしても T30 が変わらないのに曲率が 10〜25% 出続けた。
つまり**反射回数の不足が原因ではない**。

2×3×1 m という極端に小さい平行面の室で、面ごとに吸音率が大きく違うため、
**音場が拡散せず本当に多段減衰している**と考えられる（EDT と T30 の差にも表れている）。

「nref の不足が主な原因です」と決めつけていた警告文を、
反射回数不足と非拡散音場の両方を挙げる形に直した。
