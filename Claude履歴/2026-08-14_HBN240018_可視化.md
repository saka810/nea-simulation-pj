## 1. 統計残響式（Sabine / Eyring / Millington）

`reverberation.statistical_reverberation()`。
音線を飛ばさず、**室容積と各面の面積・吸音率だけ**から残響時間を出す。

共通形は `T = 24 ln(10) V / (c A)`（係数は c=343 のとき 0.161）で、
等価吸音面積 A の作り方が 3 通り。

| 式 | A | 向いている場面 |
|---|---|---|
| Sabine | `S·ᾱ + 4mV` | 吸音率が小さいとき（〜0.2） |
| Eyring | `-S·ln(1-ᾱ) + 4mV` | 吸音率が大きいとき |
| Millington | `-Σ Sᵢ·ln(1-αᵢ) + 4mV` | **面ごとに吸音率が大きく違うとき** |

test.dxf は床・壁・天井で吸音率が大きく違うので Millington も入れた。

**要点**

- **閉じた室が前提。** `statistical_reverberation_from_model()` は `model.is_closed` を見て、
  開いていれば None を返して警告する
- **`Mesh` が持つ垂直入射吸音率を Paris の式で乱入射に変換してから使う**。
  統計式は拡散音場が前提なので乱入射吸音率を要求する。
  変換しないと吸音を過小評価して残響時間が長く出る
- 空気吸収の項 `4mV` も `atmosphere` から入る
- 係数を 0.161 に固定せず、**大気条件から求めた音速**で `24ln(10)/c` を計算する

**突き合わせ（test.dxf、音線 20000 本・反射 120 回）**

| 周波数 | T30（計算） | Sabine | Eyring | T30/Eyring |
|---|---|---|---|---|
| 63 Hz | 0.088 | 0.205 | 0.182 | 0.48 |
| 125 Hz | 0.150 | 0.191 | 0.168 | 0.89 |
| 500 Hz | 0.122 | 0.128 | 0.105 | 1.17 |
| 2000 Hz | 0.104 | 0.106 | 0.083 | 1.26 |
| 8000 Hz | 0.081 | 0.100 | 0.079 | 1.03 |

**125 Hz 以上は 0.89〜1.26 で概ね合う。** 63 Hz が外れるのは帯域幅×減衰時間が
小さすぎる（BT ≒ 4）ためで手法の限界。
これで **E-15（曲率が大きい件）は「大きな計算誤りではない」ことが確認できた**。

副次的に、Paris の式の逆解き（二分法が数値積分を 200 回呼ぶ形）が重かったので、
`statistical_absorption` の既定を解析解に切り替えた（数値積分との一致は確認済み）。

## 2. G-1 音線の可視化 / G-2 音粒子の可視化

`geosim/view_rays.py` を新設。`RayRecorder` が保存した npz を読み、
`view_model_gui` のモデル表示に重ねる。

```
python view_rays.py ..\test.dxf ..\結果\test_raylog.npz --received-only --max-reflection 3 --color time
python view_rays.py ..\test.dxf ..\結果\test_raylog.npz --mode particles
python view_rays.py ..\test.dxf ..\結果\test_raylog.npz --mode particles --movie 広がり.gif
```

### やってみて分かったこと

**音線は本数を絞らないと読めない。**
最初に 250 本 × 13 反射を描いたら線が重なって完全に読めない画になった。
既定を 80 本に下げ、`--max-reflection` で**折れ線を途中で打ち切れる**ようにした。

> ここは仕様を一度作り直した。最初 `--max-reflection` を
> 「その回数**以下**の音線だけ残す」フィルタとして実装したが、
> 閉じた室では全音線が上限まで反射するので**何も残らなかった**。
> 「途中まで描く」動作に変えたら意図どおりになった。

受音した経路だけを見る（`--received-only`）のがいちばん分かりやすい。

**音粒子は逆に全音線ぶん出したほうがよい。** 点なので重なっても密度として読めるうえ、
本数が多いほど「広がり」が見える。

### 実装上の要点

- **任意時刻の粒子位置を全音線ぶんまとめて計算する**（`RayLog.positions_at`）。
  可変長の軌跡を「行ごとに揃えた 2 次元配列（末尾を +inf で埋める）」に直しておくと、
  `(距離 <= d) の個数 - 1` で区間の添字が求まり、音線ごとの `searchsorted` が要らない。
  `RayTrajectory.position_at()` を毎フレーム本数分呼ぶより速く、**結果は完全に一致**（テスト済み）
- **点群は 1 つの actor にまとめる**。音線ごとに actor を作ると本数分の描画呼び出しになる
- 動画は追加の依存を増やさず **Pillow で GIF**（60 コマ 960×720 で 3.3 MB）

### 踏んだバグ（自分のミス）

| 内容 | 原因 |
|---|---|
| 粒子が 1 つも描かれない（ラベルは 1313 個と出るのに） | `PolyData.points` を差し替えても**頂点セルが古いまま**だった。`verts` も毎フレーム作り直す必要がある |
| `AttributeError: 'CornerAnnotation' object has no attribute 'SetInput'` | `add_text(position="upper_right")` は CornerAnnotation を返す。毎フレーム書き換えるので座標指定にして vtkTextActor を得るようにした |
| `--max-reflection` を指定すると「音線がありません」 | 上記のとおり仕様の取り違え |
| カラーバー・スライダの見出しが豆腐 | VTK の既定フォントは日本語不可。ここだけ英字にした（本文側は日本語フォント指定済み） |

**GUI の全体設計（G-7）は依頼どおり後回し。**
「見るための最小限」に留めてあり、将来 GUI に組み込むときは
`RayLog` と `ParticleAnimation` をそのまま使える形にしてある。

## 3. ユーザー確認で見つかった不具合と要望（同日追記）

実際に表示してもらったところ、2 点。

### 3.1 スペースキーで再生されない（不具合）

「コマ送りはできるが再生されない」という報告。
調べたところ **VTK のタイマーが発火していなかった**。
`Plotter.add_timer_event()` で 20 回 × 50 ms なら 1 秒で終わるはずが、
**60 秒経っても 0 回**。キーイベント自体は効いていたので、
スペースで内部フラグは切り替わるがコマを進める側が動かない、という症状だった。

VTK の `CreateRepeatingTimer` は interactor の初期化後でないと効かないが、
pyvista の API は `show()` より前に呼ぶ形になっているためと思われる。

**`show(interactive_update=True)` で非ブロッキング表示にして、こちらのループから
`update()` を呼ぶ方式に変更**（`run_animation`）。45 コマ 1.5 秒で回ること、
一時停止が効くことを確認。→ **ユーザー側でも再生・停止・再開を確認いただけた**。

### 3.2 壁の透過をレイヤごとに設定したい（要望）

`view_model_gui.add_opacity_control()` を追加。

- 左の縦スライダで不透明度を設定
- `Tab` で対象を切替（すべて ↔ 各レイヤ）
- `m` でモデル表示 ON/OFF
- 起動時指定は `--opacity`（全体）と `--layer-opacity "1=0.6,2=0.05"`（レイヤ別）

モデルビューア単体（`view_model_gui.py`）でも使えるようにした。

> pyvista の `add_slider_widget` は**生成時にコールバックを 1 回呼ぶ**ので、
> そのまま作るとレイヤ別に指定した値がスライダの初期値（全レイヤの平均）で
> 上書きされてしまう。`ready` フラグでその 1 回を無視している。

### 3.3 誤診した件（記録として残す）

ウィンドウ終了時に OpenGL のエラー（`Could not create shader object` /
`Hardware does not support the number of textures defined`）が大量に出ていたため、
**「毎フレームの頂点セル再構築で GPU 資源が枯渇してクラッシュした」と誤って判断**し、
その旨をコードのコメントに書いてしまった。

実際は**ユーザーがウィンドウを閉じただけ**で、あのエラーはコンテキスト破棄時に出る
ただのノイズだった（正常に動いていた回にも出ていた）。コメントは事実に合わせて訂正済み。

※ そのとき入れた「点群を固定トポロジにする」変更自体は、
  毎フレームのジオメトリ組み直しを避けられるので残してある（6000 コマ 60 fps を確認）。
