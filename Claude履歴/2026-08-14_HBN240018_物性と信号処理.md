## 対応

### 1. `atmosphere.py` を新設（音速・空気吸収）

定数・近似式をやめ、**温度・湿度・気圧から計算**する形にした。
基準状態は **20℃ / 湿度 40% / 101.325 kPa**（40% は元コードの空気吸収近似が
想定していた条件に合わせた）。

**音速**は湿り空気の状態方程式 `c = sqrt(γRT/M)` から。
水蒸気（18.0 g/mol）は乾燥空気（28.96 g/mol）より軽いので、
湿度が上がると平均モル質量が下がって音速は速くなる。

| 条件 | 音速 | 検証 |
|---|---|---|
| 0℃ / 0% | 331.39 m/s | 標準値 331.3〜331.5 ✓ |
| 20℃ / 0% | 343.31 m/s | 標準値 343.2 ✓ |
| **20℃ / 40%（基準）** | **343.81 m/s** | |
| 14℃ / 40% | 340.12 m/s | **元コードの 340.0 はおよそ 14℃ 相当と判明** |

**空気吸収**は **ISO 9613-1** に置き換えた。古典吸収＋回転緩和と、
酸素・窒素の振動緩和の和で、後者は湿度に強く依存する。

| 20℃ 70%RH | 1 kHz | 4 kHz |
|---|---|---|
| 本実装 | 4.98 dB/km | 23.1 dB/km |
| ISO の代表値 | 約 4.8 | 約 26 |

元コードの近似（`1.81e-8 * f^1.57`）は 1k〜8k では ±20% で合うが、
**低音側は ISO の 1/3 程度しかなかった**。比較用に `legacy_absorption_coefficient()` に残した。

`Atmosphere` クラス 1 つを引き回す設計にしたので、音速と空気吸収の条件が食い違わない。
GUI からは温度・湿度のスライダをこのクラスに結ぶ。→ **TODO E-9 解決**

### 2. `absorption.py` を新設（材料ライブラリ・Paris の式）

#### 吸音率の種類の変換（TODO D-7 解決）

Paris の式

```
α_s = 2∫₀^{π/2} α(θ) sinθ cosθ dθ = (8/z²)[(1+z) - 2ln(1+z) - 1/(1+z)]
```

を**数値積分で実装し、二分法で逆解き**して残響室法 → 垂直入射の変換を行う。

> **解析解の式を最初に間違えて書いた。** 記憶で `(8/z)[1 - ln(1+z)/z + 1/(1+z)]` と
> 書いたところ数値積分と全く合わず、置換積分（μ = cosθ、u = zμ+1）で導出し直した。
> 数値積分を先に実装しておいたおかげで気づけた。

**α_s は z について単調ではない**のがポイント。z→∞（硬い壁）でも z→0（軟らかい壁）でも
α_s→0 になり、その間の z ≈ 1.567 で最大値 **0.951** を取る。
つまり 1 つの α_s に z が 2 つあるので、建築材料が乗る **z ≥ z_max の枝**を選ぶ。
0.951 を超える値（残響室法では 1 を超えることすらある）は上限に丸めて警告する。

| 残響室法 α_s | z | 垂直入射 α_n |
|---|---|---|
| 0.20 | 32.6 | 0.116 |
| 0.50 | 9.66 | **0.340** |
| 0.80 | 3.88 | 0.652 |

**残響室法の値をそのまま垂直入射として使うと吸音を大幅に過大評価する**（0.50 → 0.34）。
CSV には `# kind: normal|random` で種類を宣言する。宣言も指定も無ければ警告を出す。

### 3. バンド数を 8 に（可変）

既定を **8 バンド（63〜8k Hz）** に変更。6 バンド（125〜4k）も `--bands 6` で使える。
バンド数が表と計算で違う場合は端を複製／切り詰めして合わせ、注意を表示する。

元コードは 6→32 バンドの対応表を手書きしていたが、
**対数軸で中心周波数が最も近いものを選ぶ規則**に置き換えた。
この規則は 6 バンドのとき**元コードの手書き表を完全に再現する**（テストで確認）。

### 4. 鏡像の式のメモ → `docs/議論_鏡像の式のabs問題.md`

図と数式で段階を踏んで説明し直した。要点:

- 符号付き距離 `s = n·p + d` は「距離＋どちら側にいるか」を表す
- 鏡像は `p' = p - 2s·n`。**法線方向の成分だけ符号を反転させる**操作
- 元コードは `|s|` を使っているので、**p が裏側（s<0）にあると移動の向きが逆になる**
- 凸な部屋では虚音源が常に表側にあるので**実害が出ない**（test.dxf で完全一致を確認済み）
- 凹んだ形状・宙に浮いた物体・法線反転モデルでは崩れる
- 誤りは「**あるはずの経路を見落とす**」方向に効くので**気づきにくい**

**判断待ち**の選択肢（A: 現状の符号付き / B: 元コードに合わせる / C: 切り替え可能）と、
NEA 側に確認したいこと（凹形状での使用実績、`ynnmrev='y'` の使用実績、却下率の記録）を書いた。

### 5. 信号処理を scipy に

| 処理 | 元コード | 本実装 |
|---|---|---|
| FFT | 自作 Cooley-Tukey | `scipy.fft` の `rfft` / `irfft` |
| バンドパス FIR | 自作 `fir1_bandpass` | `scipy.signal.firwin(..., scale=False)` |
| 負の周波数への拡張 | 手動でエルミート対称に詰める | **不要**（`irfft` が前提として持っている） |
| 畳み込み | 巡回畳み込み | ゼロ詰めして線形畳み込み |
| オクターブフィルタ（残響） | 自作 FIR | `scipy.signal.butter` + `sosfilt`（**IEC 61260**） |
| フィルタ長 | nn = 131072（遅れ 1.49 秒） | 既定 8192（遅れは出力から除去） |

`scale=False` が要点。scipy は既定で通過域ゲインを 1 に正規化するが、
それをすると**バンドを足し合わせたときに平坦にならない**。
元コードの `fir1_bandpass` は正規化していないので `scale=False` が対応し、
**相対誤差 1e-16 で一致**する（元コードの移植版を `_fir1_bandpass_fortran()` に残して比較）。

**結果として、元コードにあった 1.49 秒の遅れは無くなった。**
インパルス応答は 0 秒が音の始まりで、長さは `max_time` そのもの。

残響時間のオクターブフィルタは Butterworth（因果 IIR）にしたので、
プリリンギングの回り込みが**構造的に起きない**。FIR 線形畳み込みと精度は同等
（誤差の中央値 1.0〜1.9%）で計算量は桁違いに少ない。`method='fir'` も選べる。
