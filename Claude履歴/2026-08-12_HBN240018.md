#### backtrace.f90 524〜717 行 traceff まわりの読み解き（他端末参照用）

- `tractmp(0:nref+1)`：ray ごとに `tractmp(0) = -1`、それ以外は `0` で初期化（536〜542行）。
  `tractmp(k+1) = jtmp`（677行）で「反射回数ループ k 周目の終端で反射する壁番号」を書き込む。
- 受音判定（663行）は `tractmp(k+1)` の書き込み（677行）**より前**にある。
  → 受音時点の `tractmp(1..k)` は「そこまでに済んだ k 回の反射」の履歴。今から当たる壁は履歴に含めない。これが正しい順序。
- **疑問1（do j を k ループの外に出せるか）→ 出せない**。受音は 1 本の音線で複数回（別々の k で）起こりうるので、
  受音の瞬間ごとにスナップショットを取る必要がある。
- **疑問2（ループ回数）→ nray*nref*nref にはならない**。`do j = 0, nref` のコピーは受音した時だけ（count 回）走る。
  Fortran は固定長 2 次元配列なので行まるごと（末尾の 0 込みで）コピーしているだけ。
  Python では `list(reflectionmeshid_history)` の **コピー1回** で等価。
- **疑問3（do j = 0, k で良いか）→ 良い**。k+1 以降は必ず 0 なので情報量は同じ。
  Fortran で 0 埋めが要るのは固定長配列＋別途 `traceffn(count)`（有効反射回数）で行長を管理しているため。
  Python の可変長リストなら 0 埋めは不要。
- **疑問4（inside かつ collision を条件にして良いか）→ 良くない**。両者は独立。
  `tractmp` への追記は **collision のたびに無条件**、`traceff` への追記は **inside のたび**。
  現状の Python は「inside の時だけ履歴へ append」「2次元リストへは k ループ毎周 append」で逆になっている。
- 対応方針（Python）：`if inside:` の中で `history_2dim.append(list(history))`、
  `if collision:` の中で無条件に `history.append(mesh_nearestid)`。

#### 「元の数式はしっかりした数式か？」→ **はい、正しい式です**

`energy_decay`（元コード1093行）の反射率は **局所反応性（locally reacting）壁面の斜入射圧力反射率**。導出は

1. 法線入射吸音率 α₀ から法線入射の圧力反射率 |R₀| = √(1 − α₀)
2. 規格化音響インピーダンス（実数と仮定） z = (1 + |R₀|) / (1 − |R₀|)
3. 斜入射の圧力反射率 R(θ) = (z·cosθ − 1) / (z·cosθ + 1)
4. 分母分子に (1 − |R₀|) を掛けて整理 →
   R(θ) = ((1+√(1−α₀))·cosθ − (1−√(1−α₀))) / ((1+√(1−α₀))·cosθ + (1−√(1−α₀)))

これは元コードの式そのもの。エネルギー反射率は |R(θ)|²。挙動も妥当（θ→90° で |R|→1＝掠め入射は吸音されない、
θ=0 で残存エネルギー = 1 − α₀）。

**旧実装がなぜ致命的だったか**：第2項も `(1 + √(1−α))` だと分母分子から共通因子 (1+√(1−α)) が約分され、
`R = (cosθ − 1) / (cosθ + 1)` になる。つまり **吸音率がまったく効かず**、しかも垂直入射（cosθ=1）で R=0、
すなわち**どんな材料でも完全吸音**という挙動になっていた。

**注意点**：`abs(...)**2 * enertmp(l)` を「2乗の後に自身を掛けている＝3乗では？」としたコード内の疑問は誤読。
2乗するのは圧力反射率 R、最後に掛ける `enertmp` は累積エネルギーで別物。
また想定は**垂直入射吸音率**。NEA でよく使う残響室法吸音率は 1 を超えることがあり `sqrt(1 - α)` が NaN になるため、
Paris の式を逆解きして α₀ または z を求める前処理が別途必要（未実装、要検討）。
