#### backtrace.f90 524〜717 行 traceff まわりの読み解き（他端末参照用）

- `tractmp(0:nref+1)`：ray ごとに `tractmp(0) = -1`、それ以外は `0` で初期化（536〜542行）。
  `tractmp(k+1) = jtmp`（677行）で「反射回数ループ k 周目の終端で反射する壁番号」を書き込む。
- 受音判定（663行）は `tractmp(k+1)` の書き込み（677行）**より前**にある。
  → 受音時点の `tractmp(1..k)` は「そこまでに済んだ k 回の反射」の履歴。今から当たる壁は履歴に含めない。これが正しい順序。
- **疑問1（do j を k ループの外に出せるか）→ 出せない**。受音は 1 本の音線で複数回（別々の k で）起こりうるので、
  受音の瞬間ごとにスナップショットを取る必要がある。
- **疑問2（ループ回数）→ nray*nref*nref にはならない**。`do j = 0, nref` のコピーは受音した時だけ（count 回）走る。
  Fortran は固定長 2 次元配列なので行まるごと（末尾の 0 込みで）コピーしているだけ。
  Python では `list(reflectionmeshid_history)` の **コピー1回** で等価。
- **疑問3（do j = 0, k で良いか）→ 良い**。k+1 以降は必ず 0 なので情報量は同じ。
  Fortran で 0 埋めが要るのは固定長配列＋別途 `traceffn(count)`（有効反射回数）で行長を管理しているため。
  Python の可変長リストなら 0 埋めは不要。
- **疑問4（inside かつ collision を条件にして良いか）→ 良くない**。両者は独立。
  `tractmp` への追記は **collision のたびに無条件**、`traceff` への追記は **inside のたび**。

#### 「元の数式はしっかりした数式か？」→ **はい、正しい式です**

`energy_decay`（元コード1093行）の反射率は **局所反応性（locally reacting）壁面の斜入射圧力反射率**。導出は

1. 法線入射吸音率 α₀ から法線入射の圧力反射率 |R₀| = √(1 − α₀)
2. 規格化音響インピーダンス（実数と仮定） z = (1 + |R₀|) / (1 − |R₀|)
3. 斜入射の圧力反射率 R(θ) = (z·cosθ − 1) / (z·cosθ + 1)
4. 分母分子に (1 − |R₀|) を掛けて整理 →
   R(θ) = ((1+√(1−α₀))·cosθ − (1−√(1−α₀))) / ((1+√(1−α₀))·cosθ + (1−√(1−α₀)))

これは元コードの式そのもの。エネルギー反射率は |R(θ)|²。挙動も妥当（θ→90° で |R|→1＝掠め入射は吸音されない、
θ=0 で残存エネルギー = 1 − α₀）。

**旧実装がなぜ致命的だったか**：第2項も `(1 + √(1−α))` だと分母分子から共通因子 (1+√(1−α)) が約分され、
`R = (cosθ − 1) / (cosθ + 1)` になる。つまり **吸音率がまったく効かず**、しかも垂直入射（cosθ=1）で R=0、
すなわち**どんな材料でも完全吸音**という挙動になっていた。

**注意点**：`abs(...)**2 * enertmp(l)` を「2乗の後に自身を掛けている＝3乗では？」としたコード内の疑問は誤読。
2乗するのは圧力反射率 R、最後に掛ける `enertmp` は累積エネルギーで別物。
また想定は**垂直入射吸音率**。NEA でよく使う残響室法吸音率は 1 を超えることがあり `sqrt(1 - α)` が NaN になるため、
Paris の式を逆解きして α₀ または z を求める前処理が別途必要（未実装、要検討）。

#### 回答：面エンティティにしてもねじれは直らない

3DFACE もポリフェイスメッシュも頂点ごとに z を持てるので、4 頂点なら同じようにねじれる。
効くのは**構造的に平面が保証される描き方をすること**。保証の強い順に：

| 作図方法 | 平面性 | 理由 |
|---|---|---|
| **三角形で作る** | **原理的に必ず平面** | 3 点は必ず 1 つの平面を張る |
| **UCS を作業面に合わせて `PLINE`**（LWPOLYLINE） | **構造的に必ず平面** | 頂点が xy のみ、高さはエンティティ全体で 1 つ（グループコード 38）。ねじれる余地がない |
| **直線の辺を押し出す**（`EXTRUDE` / 立ち上げ） | **必ず平面** | 直線 + 平行移動は必ず 1 つの平面を張る |
| 平面で描いてから `3DROTATE` / `ALIGN` | 保たれる | 剛体変換は平面性を壊さない |
| `3DPOLY` / `3DFACE` で 3D 空間に直接描く | **ねじれうる** | 頂点ごとに z を持てる。`test2.dxf` はこの形式 |

推奨手順（傾いた面）:
```
UCS → 3P（3点指定）または UCS → OB（既存面）で作業面を決める
PLINE で閉じた輪郭を描く   ← LWPOLYLINE になるので平面が保証される
UCS → W（ワールドに戻す）
```

**AutoCAD 内での平面性チェックの裏技**: `REGION` は定義上「平面領域」なので、
**平面でない閉じた輪郭には失敗する**。平面性の検算に使える
（確認後は REGION を削除してポリラインのまま書き出す。REGION 自体は本ツールでは読めない）。
`UCS → OB` でポリラインを指定する方法も同様。

#### 確定した法線の向きの方針

**法線は「音が通る空気側」を向く。その正解を持っているのは CAD モデル自身。**

- 室の外殻 → 室内向き ／ 室内に置く物体（机・什器）→ 外向き ／ 一面反射板 → 反射させたい側
- **両面で反射させたいものは CAD 側で厚みを持たせる。**
  室内の厚みのある机（脚は省略）なら **上面は上向き法線、下面は下向き法線**となり、
  どちらも空気側を向く。1 枚の面では片側しか反射しないので厚みが必要
- 片面だけで良ければ、反射させたい側に法線を向けてモデルを作る
- **最終的には GUI 上で法線の向きを調整できるようにしたい**（ユーザー要望 → TODO G-8）

#### 修正内容

- **既定を `'auto'` → `'cad'` に変更**。読み込み側は勝手な補正をしない
- **`'toward'` / `'away'` / `'inward'` / `'outward'` / `'auto'` を廃止**（`ValueError`）。
  面ごとに音源方向や重心方向へ向ける方式は凸凹の壁・浮いた家具で破綻するため。
  `reference_point` を渡すと理由付きで警告する
- 残したのは 3 つだけ：
  - `'cad'`（既定）… CAD の巻き順をそのまま使う
  - `'flip'` … 全反転（**元コード `ynnmrev='y'` に相当**）
  - `'shells'` … シェル単位で空気側へ揃える（外殻は内向き、内側は外向き）。
    面ごとにいじるのではなく**閉じたシェル単位で一括反転**するので凸凹があっても壊れない
- **シェル診断を新設**（勝手に直すのではなく、誤りを可視化する方向へ）
  - `mesh_shells()` … 辺の共有で連結成分（シェル）に分割
  - `analyse_shells()` … シェルごとに 閉/開・体積・法線の向き・外殻かを返す
  - `winding_is_consistent()` … 同じ有向辺が 2 回現れないかで巻き順の一貫性を判定
    （巻き順が揃った面同士が共有する辺は互いに逆向きに現れるはず）
  - `summary()` がシェルごとに「OK」「★要確認（outward が空気側）」まで表示

#### 実装内容（read_dxffile.py の本実装）

- パーサは**自前**（B-2）。ASCII DXF は「グループコード / 値」が 1 行ずつ交互に並ぶだけなので、
  2 行ずつ読んでタプル列にすれば済む。`ezdxf` を入れる理由がなかった。
  エンコーディングは UTF-8 → CP932 → latin-1 の順に試す（日本語レイヤ名対応）
- `read_model()` が `DxfModel`（mesh / source_points / receiver_points / unit_scale /
  layer_counts / skipped / extents）を返す。`read()` は mesh だけ返す簡易版
- 読むエンティティ: POLYLINE ポリフェイスメッシュ（`70`&64）、その VERTEX（`70=192` 座標 /
  `70=128` 面レコード）、**3DFACE**（B-8）、POINT（src/rec）
- 四角形以上は扇状に三角形分割。縮退面（`|n|<1e-12`）は捨てて件数を記録
- **単位の自動換算（B-5）**: `$INSUNITS` のコード 18 種 → m。`unit='mm'` / `unit=0.001` で上書き可
  （`$INSUNITS=0` の unitless 対策）
- **法線の向きの自動判定（B-6）**: 符号付き体積 V=(1/6)Σx₁·(x₂×x₃) の符号で判定し、
  V>0（外向き）なら全反転。**閉じた形状なら非凸でも正しい**のが重心方式より優れる点
  （L字型の室では重心が壁の裏に来て誤判定する）。法線だけ反転すれば足りる
  （内外判定は外積の内積の符号なので巻き順反転で値が変わらない）
- **音源・受音点の読み込み（B-7）**: `src`/`rec` レイヤの POINT。大文字小文字は無視、
  `source`/`receiver`/`音源`/`受音点` も可。複数点も読める（パイプラインは先頭のみ使用）
- **吸音率CSV（B-4）**: `read_absorption_csv()`。1列目=レイヤ名（日本語可）、2〜7列目=a1〜a6。
  サンプル `data/absorption_sample.csv` を作成。未登録レイヤは既定 0.1 でレイヤ名を列挙して警告
- `procedure.process()` に `absorption_csv` / `unit` 引数を追加。
  `soundsource_point=None` / `reciever_point=None` を渡すと DXF 側の値を使う

#### 新設: geosim/ray_recorder.py（可視化用の軌跡レコーダ）

本線（受音経路の反射面ID列）とは**別チャンネル**。`recorder=None` なら一切動かないので
本番計算の速度・メモリに影響しない。分けた理由は「本線は受音経路しか残さないが、
可視化で見たいのは音の広がりなので受音しなかった音線も要る」から。

記録内容: 節点座標 / 音源からの累積距離 / 反射面ID / バンド別エネルギー / 受音イベント / 終了理由
→ `traj.times(c)` で到達時刻、`traj.position_at(t, c)` で任意時刻の音粒子位置（線形補間）。
保存は `save_npz()`（可変長なので連結＋オフセット方式）。

**間引きは「絶対本数の上限（既定2000）＋等間隔ストライド」を既定にした**。総数比 1/100 だと
100万本→1万本（重すぎ）、1000本→10本（少なすぎ）で描画本数が安定しないため。
絶対本数なら音線数を変えても見た目の密度が変わらず比較しやすい。

#### ついでに整理: loop_deleteredundancy.py

- 毎回数百行を吐いていたデバッグ print を削除（パイプラインが通るようになって顕在化した）
- `set` → `dict.fromkeys` に変更。入力順を保って**結果を決定的に**するため
  （`set` だと実行のたびに順序が変わり突き合わせがしづらい）。結果は等価（234→214 で一致）
- 「何をしているか分からない」とあった元コードの意図を確定してコメント化。
  `traceffn` は固定長配列の 0 埋めを走査して有効反射回数を求めるもので、Python では `len()` 相当。
  ソートは「反射回数が違えば重複しない」を使った比較対象の絞り込み（高速化）だった。
