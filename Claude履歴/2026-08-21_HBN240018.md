## 2. 高速化（F-4 / F-5 / F-6 / F-7a）

ユーザー指摘 3 つがそれぞれ効いた。

### ① 同一平面パッチ単位の交差判定（F-4、前日 705ccf6）

> 三角形要素で分割しているのは、ねじれのない面を定義する必要があるため。
> ねじれの無い平面であれば、多頂点要素でも良いのでは？

そのとおりだった。判定 **2.3〜3.0 倍**。★**受音経路が 2.2 倍**になった副産物のほうが大きい
（三角形単位だと「同じ壁の隣の三角形に当たっただけ」でバックトレースが却下していた）。

### ② バックトレースの配列演算化（F-5）

全経路を同時に、反射回数 k を大きいほうから 1 段ずつ下ろす。
「長さ L の経路は k = L のときに入る」と考えると動いている経路は常に同じ k にいる。
**28.7 倍**（31.54 秒 → 1.10 秒）。1 本ずつの `backtrace_path` は参照実装として残す。

### ③ 音線追跡を受音点間で共有（F-6）

> 一回の音線追跡で受音判定はできないですか？

コードを読むと**追跡は受音点に依存していなかった**（受音しても音線は打ち切られない）。
受音球を複数置いて同時に判定するようにした。

    研修室 / 音線 6,000 本 / 160 反射 / 受音点 5 点
      旧 142.0 秒 → 新 13.2 秒（10.7 倍）。全 5 点で結果は完全一致

### ④ 複数音源の追跡（F-7a）

音線は音源から出るので共有できないが、**音源ごとの音線を 1 本の配列に並べて追跡**。
戻り値は `[音源][受音点]`。パイプライン統合（F-7b）は設計まで。

段階別の内訳が変わった：以前は 追跡 34%（×受音点数）／バックトレース 65%（×受音点数）。
いまは追跡は 1 回で共有、バックトレースは 28.7 倍。

### 依頼③ STI（G-27）

IEC 60268-16。**インパルス応答を帯域分割して積分せず、パルス列から直接
変調伝達関数 m(F) を出す**（フィルタの遅れや裾の影響を受けない。幾何音響では普通この形）。

    m(F) = |Σ E_i e^{-j2πF t_i}| / Σ E_i
    実効SNR = 10log10(m/(1-m)) を ±15 dB に丸める → TI → MTI → STI

- 男声・女声の両方を出す（女声は 125 Hz の寄与ゼロ）。評価区分（優/良/可/不可/劣）も
- 背景騒音と聴覚マスキングは **PWL と騒音レベルの両方があるときだけ**効かせる
- **6 バンド（125〜4k）では 8 kHz が無い**ので重みを外して正規化し直し警告する
- 検算：指数減衰の MTF が解析解 `1/√(1+(2πFT/13.8)²)` と 1e-6 で一致。
  T=1 s の STI が文献値 0.59 と一致

**研修室の STI 平均 0.852（優）／ばらつき 0.047**（rec1〜rec5 で 0.827〜0.874）。
C50 が 15 dB 出ていたのと整合する。

### 依頼④ 帯域別の音圧レベル（G-28）

> 無響室の計算で逆二乗がどれくらい成り立っているかを確認したりしたい。
> 点音源の PWL を与えれば絶対値も、未入力の場合は相対値でも良い。

    E_i = A_i · exp(-m·d_i) / (4π d_i²)      ← パルス列には距離減衰が入っていない
    Lp  = Lw + 10log10(Σ E_i) + 10log10(ρc/400)

★**逆二乗則が実装の物差しになった。**反射面が無ければパルスは直接音 1 本だけで
`Σ E_i = 1/(4πd²)` なので `Lp = Lw − 20log10 d − 11` に**厳密に一致**する
（実測の差 1e-14 dB、距離 2 倍で 6.02 dB 減）。
`spl.csv` / `spl.png` / まとめ表に**自由音場との差**を必ず並べてあり、
0 dB なら逆二乗どおり、外れた分が室の効きになる。

- PWL 未入力なら **Lw = 0 dB（1 pW 基準）として相対値**。出力にどちらか書く
- 成分に分けて出す（直接音 / 反射音 / 初期 50 ms / 後期 / A 特性）
- `atmosphere` に湿り空気の密度を追加（20℃ で ρ=1.200、ρc=412.5 → 補正 +0.13 dB）

研修室（5 点）の実測：**直接音は全点で自由音場の理論値と一致**、
自由音場との差は 63 Hz で +9.7〜+15.2 dB、1 kHz で +3.4〜+7.0 dB。
音源距離 3.0 / 4.3 / 6.0 m。

### ★経路の使い回し（F-9）― 指摘のとおりだった

> 音線ループからバックトレースまでは、とくに吸音の違いは関係なく、最後の虚像法による
> 計算の時にようやく吸音の効果が反映されるのかなと思っています。つまり、わざわざ
> 最初から計算し直さなくても、最後の部分だけデータを残しておけば、データの流用および、
> 再計算時に、そこから再開できませんか？

そのとおり。整理すると吸音が効くのは**バックトレースのエネルギー計算だけ**。

| 段階 | 吸音に依存するか |
|---|---|
| ①音線追跡 | **しない**（鏡面反射だけ。受音しても打ち切らない） |
| ②重複削除 | しない |
| ③経路の検証（虚音源が成立するか） | **しない**（純粋に幾何） |
| ③'エネルギー | **する**（各反射で `|R(θ,α)|²`） |

だから経路ごとに**反射面の並び**と**各反射の cosθ**（＋時刻・距離・方向）を
`結果/recN/<室>_経路.npz` に残せば、吸音材を変えた再計算は

    E = Π_k |R(cosθ_k, α_面k)|²

の**配列の掛け算だけ**で済む。元のエネルギーと **1e-15 で一致**することを確認。

★**落とし穴を 1 つ見つけた。**交差判定のパッチは「同一平面＋辺で連結＋**同じ材料**」で
まとめているので、材料の**分け方**が変わるとパッチの切れ目が動き、見つかる経路も変わる
（吸音率の**値**を変えるだけなら変わらない）。そこで**指紋**（頂点・法線・
パッチの分け方・音源・受音点・音線数・反射回数・受音球・両面）を保存して突き合わせ、
食い違えば理由を告げて①からやり直す。**吸音率の値は指紋に入れない。**

`clear_results()` はこの npz を消さない（作り直すのに音線追跡が丸ごと要るうえ、
古いかどうかは指紋で分かる）。`--no-reuse` で使い回しを切れる。

> 面積が数字として認識されていない、他のシートも同じように数値判定されていないのが

## 9. 条件表の体裁をユーザーの作ったものに合わせた

ユーザーが 研修室 の条件表を手で作り込んでくれた（`SEQUENCE` の番号列、

| 依頼 | 対応 |
|---|---|
| 吸音率一覧は 1000 個まで | `MATERIAL_SLOTS=1000`。番号は `=ROW()-1`（行の位置＝材料番号） |
| 測定種類はリストで選ぶ | ドロップダウン（`残響室法` / `垂直入射`）。既存の表にも検証を足す |
| 条件表は 30 個枠 | `LAYER_SLOTS=30`。材料名の VLOOKUP も 30 行ぶん |
| 材料名の数式は 30 個まで | 同上。参照範囲は吸音率シートの 1000 行 |
| 安全率（0.8 掛けなど） | 列を追加。**未入力は掛けない** |
| 吸音率 2 桁・面積 1 桁 | 書式を統一（面数は整数） |
| 区分は必要か | いまの 3 値と将来ありうる値を書き残した（下記）。**まだ消さない** |

★**いちばん大きい変更は「更新をその場で直す方式にした」こと。**
これまで `update()` は xlsx を書き直していたので、ユーザーが作った体裁
（列幅・書式・`SEQUENCE`・増やした列）が消えてしまう作りだった。
**見出しの文字から列を探して**面数・面積・式だけ書き換えるようにした。
材料番号と安全率は絶対に上書きしない。

★**安全率はカタログ値に掛けてから垂直入射へ変換する。**順番が逆だと意味が変わる。
実測（研修室・全レイヤ 0.8）：平均 α 1 kHz 0.539 → 0.443、理論 T30 0.198 → 0.261 s。

### 区分について（聞かれたので）

いま入る値は 3 つ。`レイヤ`（入力）／`面ごとの指定`（`face_editor` で貼った記録）／
`（モデルに無し）`（前は書いてあったが今のモデルに無いレイヤ）。
**将来ありうるのは** `追加吸音`（客席・人・什器を形を作らず面積だけで足す。

要らないと決めたら、記録の置き場を別シートに移してから列を落とす。

## 13. 画面のバグと高速化（実行後の指摘）

### ★ウィジェットがモデル側に飛び出すバグ

吸音材のチェックボックスと方向のスライダが**3D の上に二重に描かれていた**。
原因：VTK のウィジェットは `SetEnabled(1)` のときに `FindPokedRenderer`
（マウスの下のレンダラ）で置き場を決めるので、送って隠す・出すを繰り返すうちに

`SetCurrentRenderer` でパネル側に固定して解決（テストで「3D 側のプロップ 0 個」を確認）。

### ★インパルス応答の合成（ユーザーの見立てが当たっていた）

> インパルス応答の合成が、1 受音点毎にやってるのが、遅くないかな？

段階別に測ると **合成が 14.4 秒（全体 31.1 秒の 46%）**、その中身は
**伝達関数（式2.67）の 15.7 秒**で FFT は 0.18 秒だった。
式(2.67) は「周波数の数 × パルスの数」（70,313 × 8,825）の総当たり。

**時間領域に置いてから FFT** に変えて **15.54 秒 → 0.24 秒（65 倍）**。
端数の遅延は**窓付き sinc（64 タップ）**で分配する（1〜2 タップだと高域が落ちて
実効値が 17% 減る）。T30 の差 0.0000 s / C50 の差 0.000 dB / 波形の相関 0.998。
厳密版は `method="exact"` で残した。

受音点に依らないので 1 点目の結果を配るようにした。

  **サンプル時刻へ「寄せる」**やり方で、時間領域そのものではない。窓付き sinc は
  理想遅延を帯域制限して切り詰めたものなので位相が保たれる。
  谷の周波数 厳密 5937.8 Hz → 本実装 5937.8 Hz（一致）／寄せる 5512.5 Hz（7% ずれ）。
  タップ数を増やすと単調に厳密解へ寄る。ただし**一致は帯域制限つき**なので、
  波動解と突き合わせるときは `impulse_method="exact"`（設定画面で選べる）。

  増やすと**直接音が消えた**（nfft で折り返すようにした）。
