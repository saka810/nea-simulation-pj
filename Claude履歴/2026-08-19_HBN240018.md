## 1. 渡されたモデルの中身

`.dwg`（AC1032 = AutoCAD 2018 形式）なので、まず DXF に変換して中身を見た。
変換は端末に入っている **AutoCAD 2025 の `accoreconsole.exe`**（GUI 無しのコマンド実行）。

| 項目 | 中身 |
|---|---|
| 単位 | `$INSUNITS=4`（mm） |
| 範囲 | X 0〜16145 / Y 0〜17950 / Z 0〜3000 mm（= 16.1 × 17.95 × 3.0 m） |
| 幾何 | **`3DSOLID` が 1 個だけ**（レイヤ `01_建具高さ`） |
| 音源 | `src` レイヤの `POINT` 1 個（7322.6, 14471.2, 1500.0） |
| 受音点 | `rec` レイヤの `POINT` 1 個（5663.6, 9122.0, 1200.0） |
| レイヤ | `0` / `01_建具高さ` / `src` / `rec` の 4 つだけ |

ユーザーの言う「ブロックで出来ている」は DXF 上は **BLOCK/INSERT ではなく
ACIS ソリッド（3DSOLID）**だった。BLOCKS セクションには `*Model_Space` 等の
既定のものしか入っていない。

## 2. そのまま読ませた結果

```
[read_dxffile] 三角形メッシュ: 0 枚
[read_dxffile] 読み飛ばし: {'非対応エンティティ': {'3DSOLID': 1}}
[read_dxffile] 音源: [[7.3226, 14.4712, 1.5]]
[read_dxffile] 受音点: [[5.6636, 9.122, 1.2]]
```

`read_dxffile` が読めるのは面（`3DFACE` / ポリフェイスメッシュ / 閉じたポリライン）だけ。
3DSOLID は **境界表現（B-rep）の ACIS データ**で、DXF 上は暗号化されたバイナリなので
自前パーサでは中身に手が届かない。**src / rec は正しく読めている。**

## 3. 面に変換して読ませた

AutoCAD 側で三角形に割ってから 3DFACE として書き直した。

- `CONVTOMESH`（ソリッド→メッシュ）は **accoreconsole には無い**（GUI 版のみ）。
- 代わりに **`STLOUT`** でソリッドを三角形化 → ASCII STL（68 三角形）。
- STL には レイヤが無いので、元 DXF から レイヤ名（`01_建具高さ`）・`$INSUNITS`・
  src/rec の POINT を引き継いで DXF を組み立てた（変換スクリプトは scratchpad に置いた。
  リポジトリに入れるかは**未確認**）。

読み込み結果：

```
三角形メッシュ: 68 枚
単位: 1 CAD単位 = 0.001 m（$INSUNITS=4）
レイヤ別の枚数: {'01_建具高さ': 68}
寸法: [16.145, 17.95, 3.0] m (min=[0.0, 0.0, 0.0])
シェル: 1 個 / 閉 / 体積 770.3284 m³ / 法線=outward → inward へ自動反転
面の元になったエンティティ: {'3DFACE': 68}
[check] 作図チェック: 問題は見つかりませんでした
```

- 音源・受音点とも **囲まれ度 1.0**（室内にある）。
- 総面積 **724.09 m²**、体積 **770.328 m³**。
- AutoCAD の `MASSPROP` で測ったソリッドの体積は **7.7033E+11 mm³ = 770.33 m³**、
  境界ボックスも一致。**STL の三角形分割は（面が全部平面なので）誤差なし。**

## 4. 積み残し

- **吸音面の設定**。全 68 面が同一レイヤ `01_建具高さ` なので、面ごとの吸音率を
  レイヤで振り分けられない。今回は「そこまでは不要」との指示。
  やるなら「法線の向き・座標で面を分類する」か「変換時にレイヤを振る」仕組みが要る。
- 変換スクリプト（STL→面 DXF）をリポジトリに入れるかは未決。
- 実際に音線追跡まで通してはいない（読み込みの検証まで）。
