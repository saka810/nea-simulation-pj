#### 「元の数式はしっかりした数式か？」→ **はい、正しい式です**

`energy_decay`（元コード1093行）の反射率は **局所反応性（locally reacting）壁面の斜入射圧力反射率**。導出は

1. 法線入射吸音率 α₀ から法線入射の圧力反射率 |R₀| = √(1 − α₀)
2. 規格化音響インピーダンス（実数と仮定） z = (1 + |R₀|) / (1 − |R₀|)
3. 斜入射の圧力反射率 R(θ) = (z·cosθ − 1) / (z·cosθ + 1)
4. 分母分子に (1 − |R₀|) を掛けて整理 →
   R(θ) = ((1+√(1−α₀))·cosθ − (1−√(1−α₀))) / ((1+√(1−α₀))·cosθ + (1−√(1−α₀)))

エネルギー反射率は |R(θ)|²。挙動も妥当（θ→90° で |R|→1＝掠め入射は吸音されない、
θ=0 で残存エネルギー = 1 − α₀）。

**旧実装がなぜ致命的だったか**：第2項も `(1 + √(1−α))` だと分母分子から共通因子 (1+√(1−α)) が約分され、
`R = (cosθ − 1) / (cosθ + 1)` になる。つまり **吸音率がまったく効かず**、しかも垂直入射（cosθ=1）で R=0、
すなわち**どんな材料でも完全吸音**という挙動になっていた。

**注意点**：`abs(...)**2 * enertmp(l)` を「2乗の後に自身を掛けている＝3乗では？」としたコード内の疑問は誤読。
2乗するのは圧力反射率 R、最後に掛ける `enertmp` は累積エネルギーで別物。
また想定は**垂直入射吸音率**（→ D-7）。

#### 新設: geosim/ray_recorder.py（可視化用の軌跡レコーダ）

本線（受音経路の反射面ID列）とは**別チャンネル**。`recorder=None` なら一切動かないので
本番計算の速度・メモリに影響しない。分けた理由は「本線は受音経路しか残さないが、
可視化で見たいのは音の広がりなので受音しなかった音線も要る」から。

記録内容: 節点座標 / 音源からの累積距離 / 反射面ID / バンド別エネルギー / 受音イベント / 終了理由
→ `traj.times(c)` で到達時刻、`traj.position_at(t, c)` で任意時刻の音粒子位置（線形補間）。
保存は `save_npz()`（可変長なので連結＋オフセット方式）。

**間引きは「絶対本数の上限（既定2000）＋等間隔ストライド」を既定にした**。総数比 1/100 だと
100万本→1万本（重すぎ）、1000本→10本（少なすぎ）で描画本数が安定しないため。
絶対本数なら音線数を変えても見た目の密度が変わらず比較しやすい。

### B（DXF読み込み）の実装

テスト用 `test.dxf` をリポジトリ直下に置いていただいた。

| 項目 | 内容 |
|---|---|
| 室寸法 | 2000 × 3000 × 1000 mm = 2×3×1 m |
| `$INSUNITS` | **4 = ミリメートル**（ヘッダから自動判定できる） |
| 形状 | POLYLINE ポリフェイスメッシュ 6 枚、各 4 頂点＋2 面レコード → **三角形 12 枚** |
| レイヤ | `1`=床 / `2`=壁4面 / `3`=天井 → **レイヤ名が吸音材ID**（Fortran と同じ規約） |
| POINT | **`src` レイヤ (1000,500,500)mm / `rec` レイヤ (700,2000,500)mm** |
| 巻き順 | 検算したところ CAD 時点で**すでに内向き法線** |

**DXF に音源・受音点まで入っていた**のが収穫。座標をコードに書かずに済む形にした。

#### 実装内容

- パーサは**自前**（B-2）。ASCII DXF は「グループコード / 値」が 1 行ずつ交互に並ぶだけなので、
  2 行ずつ読んでタプル列にすれば済む。`ezdxf` を入れる理由がなかった。
  エンコーディングは UTF-8 → CP932 → latin-1 の順に試す（日本語レイヤ名対応）
- `read_model()` が `DxfModel` を返す。`read()` は mesh だけ返す簡易版
- 読むエンティティ: POLYLINE ポリフェイスメッシュ、その VERTEX（`70=192` 座標 /
  `70=128` 面レコード）、**3DFACE**（B-8）、POINT（src/rec）
- **単位の自動換算（B-5）**: `$INSUNITS` のコード 18 種 → m。`unit='mm'` で上書き可
- **法線の向きの自動判定（B-6）**: 符号付き体積 V=(1/6)Σx₁·(x₂×x₃) の符号で判定
  ※翌日、開いた形状では成り立たないこと・面ごとの補正は危険であることが判明して大幅に見直した
- **音源・受音点の読み込み（B-7）**: `src`/`rec` レイヤの POINT
- **吸音率CSV（B-4）**: `read_absorption_csv()`。サンプル `data/absorption_sample.csv`
- `procedure.process()` に `absorption_csv` / `unit` 引数を追加。
  `soundsource_point=None` を渡すと DXF 側の値を使う

#### 検証（test.dxf 実物 + パイプライン 1→2→3→4 通し実行）

**数値がぴったり一致する確認**が 2 つ取れた。

- **表面積 22.0000 m²** = 2×(2×3 + 3×1 + 1×2) と厳密一致 → 三角形分割に隙間・重複なし
- **符号付き体積 −6.0000 m³** = 室容積 6 m³ の負値 → 閉じていて内向き法線
- 三角形 12 枚 / 単位換算 0.001 / 寸法 [2,3,1] m / 法線ノルム全て 1.0 / 内向き 12/12
- レイヤ別の吸音率適用 OK（床 a1=0.02, 壁 a1=0.10, 天井 a1=0.35）
- 通し実行: 音線5000本・最大反射10・受音球 r=0.15m → 受音608件 → 重複削除502経路、
  直接音14本、反射回数0〜10、全3756節点が室内
- **バンド別エネルギーが吸音率を反映**（低域 0.0391 → 高域 0.0017）
