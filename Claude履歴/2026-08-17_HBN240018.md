## 1. タイトルバーの文字化け（G-13）

### 何が起きていたか

`研修室 — 法線の確認` が **`研修室 ?E法線?E確?E`** になっていた。
面白いことに**文字によって通ったり化けたりする**（研・修・室・法・線・確は通り、
—・の・認 が化ける）。画面の中の見出しは日本語のまま正しく出ている
（こちらはフォントを指定して VTK に描かせているので化けない）。

### 調べたこと

VTK が Windows に作るウィンドウは **ANSI ウィンドウ**（`IsWindowUnicode` が偽）だった。
この端末は `GetACP() = 932`。VTK 自身は正しい文字列を持っている
（`GetWindowName()` は `'研修室 — 法線の確認'` を返す）ので、
**OS へ渡すところで壊れている**と分かった。

手は一通り試して、どれも駄目だった。

| やったこと | 読み戻した結果 |
|---|---|
| VTK の `SetWindowName`（現状） | `研修室 ?E法線?E確?E` |
| `SetWindowTextW`（ワイド文字版） | `???C?? ? ?@????m?F` ← **かえって悪化** |
| `SendMessageW` で `WM_SETTEXT` | 同上 |
| `SetWindowTextA` に CP932 のバイト列 | 同じく全部 `?` |
| ASCII のみ | **OK** |

W 系で全部 `?` になるのは、ANSI ウィンドウなので書き込み時に ANSI へ
変換されるため。その変換が CP932 ではない何かで行われているらしく、
こちらから正しいバイト列を渡す手段が無い。

### どう直したか

**設定したあと読み戻して検証し、一致しなければ英字の題に差し替える**
（`view_model_gui.set_window_title()`）。化けた文字列を出しておくよりまし、という判断。

**画面の中の見出しは日本語のまま。タイトルバーだけが英字**になる。

## 2. いまの画面を画像・動画で保存（G-12）

### 使い方

| キー | 動き | 画面 |
|---|---|---|
| `g` | いまの画面をそのまま **PNG** | 法線の確認 / 音線・音粒子 / 音線の飛び方 |
| `b` | いまの視点で **動画（GIF）** | 音粒子のとき |

**角度も、絞った本数も、不透明度も、見えているままが残る。**
左のパネルごと写す（どのレイヤを出していたか・不透明度がいくつだったかも
一緒に残るほうが、あとで見返したときに条件が分かるため）。

### 置き場と名前

**`図/画面/`** に連番で置く。撮るたびに増える（上書きしない）。

    図/画面/法線_01.png
    図/画面/音線_01.png
    図/画面/音粒子_0123ms_01.png     ← 止めた時刻を名前に入れる
    図/画面/音線の飛び方_01.png
    図/画面/音粒子_01.gif

★**`図/` の直下ではなく子フォルダにしてある。** `clear_results()` が
`図/` の PNG を消すので、同じ場所に置くと**計算し直すたびに手で撮った画像が
巻き添えで消える**。テストで押さえた。

### 動画について

GIF にした。**追加の依存を増やさないため**（Pillow は matplotlib の依存で
既に入っている。mp4 には ffmpeg が要る）。そのぶんの制約:

- 幅 720 px に縮め、コマごとに 128 色へ落とす（GIF の色数上限は 256）
- コマ数は 400 で頭打ちにして等間隔に間引く。
  離散化時間を 0.2 ms にすると 3 秒で 15000 コマになり、そのまま溜めると
  メモリが持たない。間引いたときはその旨を出す

既存の `save_movie()`（off-screen で作り直す）とは**別物**。
あちらは既定の視点で作り直す。`b` は**画面に出ているウィンドウをそのまま録る**。

### キーの選び方

`p` は VTK のピック（法線確認の「面を枠で選んで反転」）に取られているので、
撮影は **`g`（grab）**、動画は **`b`** にした。

結果、**プロセスが segfault し、そのあとしばらくこの端末では新しいプロセスでも
OpenGL のウィンドウが開けなくなった**

しばらくして復帰したが、**GUI の確認が一時できなくなった**。

直し方：**描画の外でやる。** `finish_window()` を各ビューアの `show()` の
直前に呼ぶ。そこで 1 回だけ描いてウィンドウを作らせ、そのうえで設定・検証する。

### そのほか

| 内容 | 直し方 |
|---|---|
| 描画イベントを「一度きり」にしたら、ウィンドウが出来る前に消化されて検証できなかった | ハンドルが取れるまでは「済み」にしない（この版は上の理由で結局やめた） |

## 4. 残響式の呼び名（ユーザーからの質問）

**「ミリントン？の残響式は聞いたことが無いです。アイリングヌードセンが、
空気吸収も考慮した式です。」**

### ヌードセンの指摘は正しい ― こちらの表記が間違っていた

アイリングの式そのものは `-S ln(1-ᾱ)` までで、**空気吸収の項 `4mV` を足した形は
ヌードセン（V. O. Knudsen）の寄与**。したがって空気吸収込みなら
**アイリング・ヌードセンの式**と呼ぶのが正しい。

コードは最初から `4mV` を入れていた（`include_air_absorption=True` が既定）のに、
表示だけ `Eyring` のままだった。**中身は合っていて名前が違っていた**。

表示名を直した。`statistical_labels()` が `include_air_absorption` を見て
切り替えるので、空気吸収を切れば素の `Eyring` に戻る。
直した先：コンサル出力（`reverberation` / `procedure` / `app`）、
図の凡例（`reverberation.png`）、条件入力のチェックボックス、技術説明書、
PROGRAM_STRUCTURE。**CSV の列名 `eyring_s` はそのまま**
（既存プロジェクトの読み込みが壊れるため。必要なら別途改名する）。

### ミリントンの式は実在するが、実務では使われない

**ミリントン・セッテの式**（Millington 1932 / Sette 1933）。
アイリングが**平均してから対数を取る**のに対し、**面ごとに対数を取って足す**。

    Eyring     A = -S ln(1-ᾱ)          ᾱ = ΣSᵢαᵢ / S
    Millington A = -Σ Sᵢ ln(1-αᵢ)

面ごとに吸音率が大きく違うときの理屈としては通っているが、
**αᵢ→1 の面が 1 枚でもあると `-ln(1-αᵢ)` が発散し、T→0 になる**。
開口（α=1）が 1 つあるだけで室の残響がゼロという結論になる。これが致命的で、
実務ではまず使われない。

研修室はまさにこの癖が出ている（吸音面 α=0.951 が 127 m²）。

| | 125Hz | 250Hz | 500Hz | 1kHz | 2kHz | 4kHz |
|---|---|---|---|---|---|---|
| Eyring-Knudsen | 1.177 | 0.775 | 0.410 | 0.245 | 0.271 | 0.238 |
| Millington | 1.121 | 0.725 | 0.283 | 0.130 | 0.136 | 0.129 |
| 比 | 0.95 | 0.94 | **0.69** | **0.53** | **0.50** | **0.54** |

**読むのは Sabine と Eyring-Knudsen。** ミリントンは参考値として残してあるが、
不要なら列ごと落とせる（**判断待ち**）。

## 5. 統計残響式を 3 つに（E-17）

**「Sabine，Eyring，Eyring-Knudsen の 3 つ欲しいです。ミリントンは落として良いです。」**

| 式 | 等価吸音面積 A |
|---|---|
| Sabine | `S·ᾱ` |
| Eyring | `-S·ln(1-ᾱ)` |
| Eyring-Knudsen | `-S·ln(1-ᾱ) + 4mV` |

**Sabine と Eyring には空気吸収を入れない。** 素の古典的な形にしておかないと、
Eyring → Eyring-Knudsen の差が「空気吸収ぶん」にならないため。
これで**差を読むだけで空気吸収の効きが分かる**ようになった。

研修室での実際の値:

| | 125Hz | 250Hz | 500Hz | 1kHz | 2kHz | 4kHz |
|---|---|---|---|---|---|---|
| Sabine | 1.260 | 0.859 | 0.494 | 0.332 | 0.360 | 0.336 |
| Eyring | 1.181 | 0.779 | 0.412 | 0.247 | 0.276 | 0.250 |
| Eyring-Knudsen | 1.177 | 0.775 | 0.410 | 0.245 | 0.271 | 0.238 |

空気吸収の効きは 125 Hz で 0.004 秒、4 kHz で 0.012 秒。**この室では小さい**
（容積 373 m³ と小さく残響も短いため）。大空間ほど効いてくる。

ミリントンは削除。図の凡例・CSV・コンソールの 3 か所から外した。

## 7. 数値入力で画面が落ちた（G-15）

**「条件設定を数値で指定したら、画面が落ちて、元のプロジェクト選択画面等に戻った」**

### 原因：`e` は VTK の終了キーだった

数値入力を `e` に割り当てていた。ところが **`e` は VTK では `q` と同じ終了キー**で、
押すと入力ダイアログが出ると同時に **`ExitEvent` も飛んでいた**。

`run_animation` は `ExitEvent` を見てループを抜けるので、値を入れて OK を押した瞬間に
ウィンドウが閉じ、条件入力の画面に戻る。**例外は出ないのでログにも痕跡が残らない。**
（実際、ログには可視化を開いた行の次に `[app] 閉じました` があるだけだった。）

数値入力を **`t`** に変更（`view_model_gui.VALUE_INPUT_KEY`）。

### 実測した予約キー

`InvokeEvent('CharEvent')` でキーを総当たりして調べた。

| キー | VTK の既定動作 |
|---|---|
| `e` / `q` | **終了（ExitEvent）** |
| `w` / `s` | ワイヤフレーム / 面 |
| `r` | 視点リセット |
| `f` | 注視点へ寄る |
| `p` | ピック（面の選択） |
| `u` | ユーザーイベント |
| `3` | ステレオ表示 |

`view_model_gui.VTK_RESERVED_KEYS` に明文化し、`enable_value_input()` は
予約キーを渡されたら警告を出すようにした。
**テスト [22] で「割り当てているキーが予約キーでないこと」を押さえた**（新規 14 件）。

### 遠回りした点

最初は tkinter と VTK のイベントループの入れ子（Tk の mainloop の中から
VTK を描き直している）を疑い、2 通りの再現を書いたが**どちらも落ちなかった**。
キーイベントを VTK 側から発火させる形まで作ってようやく、
`CharEvent` の総当たりで `e` と `q` だけが `ExitEvent` を出すと分かった。

**症状から原因を推測するより、全部試して観測するほうが早かった。**

### あわせて直したところ

- `normal_editor` の操作説明に数値入力（`t`）が載っていなかったので追加
  （不透明度と正面の方位の 2 つがスライダなのに、数字で入れられると書いていなかった）
- 各ビューアの docstring にも `t` と「`e` は使えない」ことを明記
