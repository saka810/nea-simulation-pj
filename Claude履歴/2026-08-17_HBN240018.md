## 1. タイトルバーの文字化け（G-13）

### 何が起きていたか

`研修室 — 法線の確認` が **`研修室 ?E法線?E確?E`** になっていた。
面白いことに**文字によって通ったり化けたりする**（研・修・室・法・線・確は通り、
—・の・認 が化ける）。画面の中の見出しは日本語のまま正しく出ている
（こちらはフォントを指定して VTK に描かせているので化けない）。

### 調べたこと

VTK が Windows に作るウィンドウは **ANSI ウィンドウ**（`IsWindowUnicode` が偽）だった。
この端末は `GetACP() = 932`。VTK 自身は正しい文字列を持っている
（`GetWindowName()` は `'研修室 — 法線の確認'` を返す）ので、
**OS へ渡すところで壊れている**と分かった。

手は一通り試して、どれも駄目だった。

| やったこと | 読み戻した結果 |
|---|---|
| VTK の `SetWindowName`（現状） | `研修室 ?E法線?E確?E` |
| `SetWindowTextW`（ワイド文字版） | `???C?? ? ?@????m?F` ← **かえって悪化** |
| `SendMessageW` で `WM_SETTEXT` | 同上 |
| `SetWindowTextA` に CP932 のバイト列 | 同じく全部 `?` |
| ASCII のみ | **OK** |

W 系で全部 `?` になるのは、ANSI ウィンドウなので書き込み時に ANSI へ
変換されるため。その変換が CP932 ではない何かで行われているらしく、
こちらから正しいバイト列を渡す手段が無い。

### どう直したか

**設定したあと読み戻して検証し、一致しなければ英字の題に差し替える**
（`view_model_gui.set_window_title()`）。化けた文字列を出しておくよりまし、という判断。

**画面の中の見出しは日本語のまま。タイトルバーだけが英字**になる。

## 2. いまの画面を画像・動画で保存（G-12）

### 使い方

| キー | 動き | 画面 |
|---|---|---|
| `g` | いまの画面をそのまま **PNG** | 法線の確認 / 音線・音粒子 / 音線の飛び方 |
| `b` | いまの視点で **動画（GIF）** | 音粒子のとき |

**角度も、絞った本数も、不透明度も、見えているままが残る。**
左のパネルごと写す（どのレイヤを出していたか・不透明度がいくつだったかも
一緒に残るほうが、あとで見返したときに条件が分かるため）。

### 置き場と名前

**`図/画面/`** に連番で置く。撮るたびに増える（上書きしない）。

    図/画面/法線_01.png
    図/画面/音線_01.png
    図/画面/音粒子_0123ms_01.png     ← 止めた時刻を名前に入れる
    図/画面/音線の飛び方_01.png
    図/画面/音粒子_01.gif

★**`図/` の直下ではなく子フォルダにしてある。** `clear_results()` が
`図/` の PNG を消すので、同じ場所に置くと**計算し直すたびに手で撮った画像が
巻き添えで消える**。テストで押さえた。

### 動画について

GIF にした。**追加の依存を増やさないため**（Pillow は matplotlib の依存で
既に入っている。mp4 には ffmpeg が要る）。そのぶんの制約:

- 幅 720 px に縮め、コマごとに 128 色へ落とす（GIF の色数上限は 256）
- コマ数は 400 で頭打ちにして等間隔に間引く。
  離散化時間を 0.2 ms にすると 3 秒で 15000 コマになり、そのまま溜めると
  メモリが持たない。間引いたときはその旨を出す

既存の `save_movie()`（off-screen で作り直す）とは**別物**。
あちらは既定の視点で作り直す。`b` は**画面に出ているウィンドウをそのまま録る**。

### キーの選び方

`p` は VTK のピック（法線確認の「面を枠で選んで反転」）に取られているので、
撮影は **`g`（grab）**、動画は **`b`** にした。

## 自分のミス

### ★タイトル設定を描画イベントの中でやり、端末の OpenGL を壊した

最初は「描画イベント（`RenderEvent`）に引っ掛けて、ウィンドウが出来た瞬間に
タイトルを設定する」形にした。理屈は合っていたが、**`SetWindowName` は
`WM_SETTEXT` を同期で送る**ため、描画の途中でウィンドウプロシージャが再入する。

結果、**プロセスが segfault し、そのあとしばらくこの端末では新しいプロセスでも
OpenGL のウィンドウが開けなくなった**
（`failed to get wglChoosePixelFormatARB` / `failed to get valid pixel format`）。
Bash からも PowerShell からも、最小の PyVista ウィンドウでも再現した。
しばらくして復帰したが、**GUI の確認が一時できなくなった**。

直し方：**描画の外でやる。** `finish_window()` を各ビューアの `show()` の
直前に呼ぶ。そこで 1 回だけ描いてウィンドウを作らせ、そのうえで設定・検証する。

### そのほか

| 内容 | 直し方 |
|---|---|
| 描画イベントを「一度きり」にしたら、ウィンドウが出来る前に消化されて検証できなかった | ハンドルが取れるまでは「済み」にしない（この版は上の理由で結局やめた） |
| `finish_window()` を `show()` の直前に呼んだのに音線の画面だけ化けたまま | **pyvista の `show()` が `self.title` を貼り直す**。決めた題を `plotter.title` にも書き戻す |
| `add_movie_key` が `animation.frames` を信じていて、`times` と食い違うと落ちた | 短いほうに合わせる |

**傾向**：ウィンドウの「いつ・どこで設定するか」を外し続けた。
描画の最中に OS を触らない／`show()` が何を上書きするかを確かめる、で防げた。
