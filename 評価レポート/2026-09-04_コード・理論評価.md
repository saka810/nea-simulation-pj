## 1. 結論

本プロジェクトは、音線法による候補経路探索と鏡像音源法による経路再構築を組み合わせ、DXF 読み込み、反射経路、周波数帯域別レベル、インパルス応答、残響・明瞭度・STI、GUI、帳票出力までを一つの流れにまとめた、機能量の多い研究・設計支援用プロトタイプである。762 件の独自テストが通り、数式単位の検証も多い点は明確な強みである。

一方で、現状を「規格準拠の実務計算ソフト」または「定量結果を無条件に信頼できる製品」と評価することはできない。主な理由は次のとおりである。

1. 残響時間が ISO 3382 系で要求される減衰曲線の線形最小二乗回帰ではなく、閾値の初回通過時刻だけで算出されている。
2. 周波数応答の空気吸収オプションが未実装であり、指定しても結果が変わらない。
3. coherent 計算で帯域別音源パワーを平均値へ潰しており、さらに総合値などが energy 計算のまま残る。
4. 受音球判定が有限線分と球の交差判定になっておらず、壁直前で交差する一部の経路を落とす。
5. STI の規格版が明記されず、現行 IEC 60268-16:2020 と一致しない係数を含む。
6. `absorption.csv` の吸音率種別と IR 絶対振幅校正が未確定で、結果の物理的意味に直結する未解決事項が残る。

総評は「よく作り込まれた研究プロトタイプ。ただし、規格準拠・校正済みの実務ツールとして公開する前に、計算の意味と適用範囲を固定する必要がある」である。

### 3.2 テスト基盤の所見

テストは幾何式、音響式、ファイル処理、各種回帰を広く覆っており、本プロジェクトの最大の資産の一つである。特に最適化版と参照版の一致、Fortran 由来式の再現、解析解との比較がある点は良い。

ただし、以下を補う必要がある。

- Windows の既定 CP932 コンソールでは、テスト出力中の `≈` により `UnicodeEncodeError` が発生する。`PYTHONUTF8=1` では全件成功した。テストコード側で出力文字を ASCII 化するか、UTF-8 を明示すべきである。

- 最適化版と参照版が同じ式を共有するテストは、実装の同等性は示すが、物理的正しさや規格準拠を独立には保証しない。

- 音線数、受音球半径、最大反射回数を変化させた収束試験と不確かさ評価が自動化されていない。
- CI 設定、カバレッジ計測、GUI の headless smoke test がない。

## 4. 重大な指摘事項

重大度は次のように定義した。

- **S1:** 計算結果の意味・規格適合性・主要出力を誤らせる。公開前に修正すべき。
- **S2:** 条件によって結果または保守性を大きく損なう。優先して修正すべき。
- **S3:** 文書、使い勝手、将来保守に関する改善事項。

### S1-1. 残響時間が ISO 3382 の回帰法になっていない

`geosim/reverberation.py` の `_decay_time()` は、Schroeder 曲線が -5 dB と -25/-35 dB を初めて下回るサンプルを探し、その 2 点間時間を外挿して T20/T30 を求める。これは減衰範囲全体に対する線形最小二乗回帰ではない。

ISO 3382 の測定法では、T30 は概ね -5～-35 dB、T20 は -5～-25 dB の減衰曲線へ直線を最小二乗適合し、その傾きから 60 dB 減衰時間を得る。閾値 2 点のみでは、ノイズ、非線形減衰、局所的な揺らぎの影響を強く受ける。技術説明書も現在の 2 点法を規格法のように説明しており、コードと文書を同時に直す必要がある。

推奨修正:

1. 指定 dB 範囲の全サンプルへ一次回帰を行う。
2. 傾き、切片、決定係数または相関係数、使用区間、ノイズ余裕を結果へ含める。
3. 減衰範囲不足、非負傾き、適合不良を `NaN` と警告で区別する。
4. 人工指数減衰に加え、二重勾配・後半ノイズを持つ IR で回帰のテストを追加する。

根拠: [ISO 3382:1997 の公開プレビュー（線形最小二乗回帰の記述）](https://cdn.standards.iteh.ai/samples/2354/da1625f2a0c9494ab0ac112528ff5850/ISO-3382-1997.pdf)、[現行 ISO 3382-1 の概要](https://www.iso.org/standard/40979.html)

### S1-2. 周波数応答の空気吸収オプションが機能していない

`geosim/frequency_response.py` の `response()` は説明式に空気吸収を含むが、`air_absorption and band is not None` の分岐が `pass` のままである。実測プローブでは、100 m、8 kHz 相当でも空気吸収 ON/OFF の差は **0.0 dB** だった。既存の空気吸収係数を適用すれば、この条件ではエネルギーレベルで約 **-13.0 dB** の差が期待される。

推奨修正:

- 経路長ごとに振幅減衰を適用する。既存係数が dB/m またはエネルギー係数のどちらかを API で固定し、振幅とエネルギーの 2 倍係数を混同しない。
- 空気吸収 ON/OFF が長距離・高周波で既知差になるテストを追加する。
- `band=None` で複数帯域のエネルギーをまとめて一つの複素伝達関数に使う現在の意味は曖昧である。帯域または周波数ごとの応答へ API を限定する方が安全である。

### S1-3. coherent 計算で音源スペクトルが失われ、出力内も不整合になる

`geosim/sound_level.py` の `coherent_band_levels()` は、帯域別 PWL が与えられた場合に `mean()` で単一値へ変換している。検証として `[80, 100] dB` の 2 帯域を入れると、1 m・単一経路の coherent 出力は両帯域とも約 79.14 dB となった。一方、通常のエネルギー計算は約 `[69.14, 89.14] dB` であり、差は `[+10, -10] dB` となる。帯域別音源スペクトルを保持していない明確な不具合である。

さらに `geosim/procedure.py` は coherent 選択時に `result["levels"]` のみ差し替え、`overall`、`overall_a`、`a_weighted`、成分別行などは energy 計算の値を残す。このため一つの結果オブジェクト内で計算法が混在する。`write_levels()` には、総合欄の `音源パワーレベル_dB` 行へ音源距離を書き込む箇所もあり、ラベルと値が一致しない。

また、反射係数はエネルギー量として絶対値化され、coherent 再構成では正の平方根・反射位相 0 を仮定する。実際の境界では反射係数が負または複素数となり得るので、現状の coherent 応答やモード図は、剛壁に近い単純条件以外では定性的表示と位置付けるべきである。

### S1-4. 受音球判定が有限経路区間との正しい交差判定ではない

`geosim/receiver_sphere.py` は、音線への垂足が球内にあり、かつ垂足距離が次の壁までの距離以下であることを要求する。これは「音源から壁までの有限線分が球と交差する」条件と同値ではない。

例として、壁まで 1.0 m、受音球中心 1.1 m、半径 0.2 m の場合、線分は x=0.9～1.0 m で球内に入るため交差している。しかし垂足の x=1.1 m が壁より先なので、現実装は False と判定する。壁近傍の受音点や受音半径が大きい条件で、候補反射履歴を欠落させ得る。

推奨修正は、球中心への投影パラメータを `[0, 壁までの距離]` に clamp し、線分上の最近点と球中心の距離を比較する方法である。接線、開始点内包、終点直前交差、中心が壁後方にあるケースをテストへ追加する。

### S1-5. STI は規格版を固定しておらず、現行版との不一致がある

`geosim/sound_level.py` には男性・女性の両方の重みが定義され、一般的に「IEC 60268-16」と記載されている。しかし IEC 60268-16:2020 は男性音声スペクトルを変更し、女性用音声スペクトルおよび重み係数を削除している。したがって現実装は旧版ベースと推測されるが、版番号がないため再現性と規格適合性を判断できない。

また、6 帯域しかない場合に 8 kHz を除外して重みを再正規化する処理は実用上の近似としては理解できるが、標準 STI そのものではない。出力名を「参考 STI（非標準帯域）」などへ分けるべきである。

推奨修正:

- 対応規格を `IEC 60268-16:2011` または `IEC 60268-16:2020` のように明記し、係数・処理をその版へ揃える。
- 旧版互換が必要なら `standard_version` を入力条件とし、帳票にも版を記録する。
- 規格例または信頼できる別実装との数値比較を追加する。

根拠: [IEC 60268-16:2020 の公式概要と変更点](https://webstore.iec.ch/en/publication/26771)

### S1-6. 吸音率の意味と IR の絶対校正が未確定

README/TODO は `absorption.csv` の値がランダム入射吸音率か垂直入射吸音率か不明であること、および IR 絶対振幅が校正されていないことを既知課題としている。これは単なる文書不足ではなく、反射ごとの減衰量、残響、レベル、STI の物理的意味に直接影響する。

実装している Paris 式による変換は、実数の局所反応インピーダンス等の仮定下では内部整合している。しかし、残響室で測った拡散入射吸音率から一意な垂直入射反射係数が得られるわけではない。入力データの測定法・適用式・上限 clamp を明示する必要がある。

この二点は、実測値と比較する製品用途のリリースゲートとすべきである。

## 5. 中程度の指摘事項

### S2-1. C50/C80/D50/Ts の原点が帯域ごとの最大エネルギーサンプル

`clarity_measures()` は各帯域の最大エネルギー位置を直接音到来とみなす。強い初期反射が直接音より大きい場合や直接音が遮られる場合、評価窓の原点が移動し、明瞭度指標が変わる。経路データが持つ直接経路時刻または幾何学的到来時刻を優先し、IR しかない場合のみ onset 検出へフォールバックすべきである。

### S2-2. 固有モード列挙が各軸 0～12 次に固定される

`modal_frequencies()` は cutoff 周波数ではなく固定次数 `orders=12` で列挙する。20×5×3 m、250 Hz 以下という例では、x 方向 20 次の約 171.9 Hz のモードさえ欠落する。各軸について `floor(2 L f_max / c)` から必要次数を計算し、cutoff で最終選別すべきである。

### S2-3. 音線探索の完全性と不確かさが結果へ現れない

候補壁列を音線で発見し、その後に鏡像音源法で厳密な反射点を再構築する設計は合理的である。ただし、一度も発見されなかった壁列は後段へ進まない。したがって反射経路の完全性は、音線数、受音球半径、最大反射回数、幾何形状に依存する。

Fibonacci 球面サンプリングは再現可能という長所がある一方、推定誤差や信頼区間は出ない。代表室ごとに N-ray と半径を振った収束表を生成し、エネルギー、RT、C80、STI の変化率を出力することを推奨する。

### S2-4. 幾何音響モデルの適用範囲を結果に表示すべき

現実装は主に鏡面反射を扱い、拡散散乱、エッジ回折、透過、複素反射位相、音源指向性をモデル化していない。この近似は波長に対して面が十分大きい中高周波の鏡面的空間では有用だが、低周波、回折が支配的な遮蔽、強い散乱面、複雑な座席・什器を含む空間で定量保証はできない。

結果帳票へ「幾何音響・鏡面反射モデル」「未考慮現象」「推奨周波数範囲」を記録した方がよい。幾何音響の適用と限界については、[室内音響シミュレーションのレビュー論文](https://doi.org/10.1121/1.4926438)も参照できる。

### S2-5. 1/1 octave から 1/3 octave への展開が入力範囲外へエネルギーを生成する

TODO に記録されているとおり、帯域端の展開によって 16～50 Hz および約 12.7～20.2 kHz にもエネルギーが割り当てられ、約 9.4% が元の入力帯域外へ出るケースがある。総エネルギー保存だけでなく、入力が定義された周波数範囲内で保存する仕様を決める必要がある。

### S2-6. DXF 対応範囲と失敗モード

独自 DXF パーサーは閉殻、法線、面積、体積、OCS 変換まで丁寧に扱う。一方、INSERT、曲線、一般的な ACIS の自動変換は限定的で、ACIS 変換は AutoCAD 依存である。生成した Faces DXF が AutoCAD で開けない既知の layer table 問題も TODO に残る。実案件の DXF コーパスを fixture 化し、対応/非対応を明確にする必要がある。

### S2-7. 凹形状での内向き法線推定

音源設置面の内向き方向は、概ね面法線と全体重心の関係から選択される。凹室、複数室、内部障害物では全体重心がその面の室内側を正しく示さない場合がある。閉殻の向き、局所点からの inside/outside 判定、またはユーザー指定ベクトルを利用すべきである。

### S2-8. 入力値の有限性検査が不足

材質値の負値は検査されるが、`NaN`、`Inf` はすり抜ける経路がある。反射係数計算で無限大や欠損値が静かに伝播すると、後段の合算や Excel 出力で原因追跡が難しい。全数値入力に `np.isfinite` と範囲検査を入れ、エラー位置を材質名・帯域付きで示すべきである。

## 6. 理論実装の評価

### 6.1 妥当性が高い部分

- 音線法で候補反射面列を集め、鏡像音源法で反射点を逆追跡し、三角形内判定と遮蔽判定を行う全体構成は合理的である。
- 鏡映点、線分・平面交点、三角形内判定などの幾何式はテストが厚い。
- 距離逆二乗、反射ごとのエネルギー係数積、空気吸収を含む経路エネルギー計算は、採用している単純モデル内では整合している。
- 大気吸収は ISO 9613-1 型の温湿度・周波数依存式として実装され、既知値テストもある。[ISO 9613-1 の公式概要](https://www.iso.org/standard/17426.html)
- Sabine、Eyring、空気吸収を含む Eyring-Knudsen 型の統計残響式は、コード内の定義と解析テストの範囲で整合している。ただし拡散音場仮定であり、非拡散室の正解値ではない。
- 経路キャッシュに幾何・音源・受音点等の fingerprint を持たせる設計は、誤キャッシュを防ぐ観点で良い。

### 6.2 規格準拠表現を弱めるべき部分

`reverberation.py` は 6 次 Butterworth の分数オクターブフィルタを「IEC 61260 Class 1 相当/準拠」と説明する。しかし IEC 61260-1 の Class 1 は、単に Butterworth 次数を選ぶことではなく、基準周波数、相対減衰、許容限界など一連の性能要求に対して検証される分類である。リポジトリには規格マスクへの適合試験がない。

現状は「IEC 中心周波数に基づく 1/1・1/3 octave Butterworth フィルタ」と表現し、Class 1 の主張は周波数応答マスク検証後に行うべきである。[IEC 61260-1:2014 の公式概要](https://webstore.iec.ch/en/publication/5063)

### 6.3 位相を扱う結果の位置付け

エネルギー音響としてのレベル・残響評価と、複素振幅を足す coherent/frequency response は必要な入力情報が異なる。吸音率だけでは複素反射係数の位相は定まらない。現実装の「反射位相ゼロ」という仮定は、研究用の可視化として明記する限り有用だが、一般材料の干渉ノッチや室モードの定量予測としては情報不足である。

推奨する整理は次のとおりである。

- energy モード: 吸音率ベースの広帯域・統計的評価。
- coherent モード: 複素反射係数を入力できる場合の波動干渉近似。
- 複素係数がない場合: 「剛壁位相近似」ラベルを付け、絶対精度保証外とする。

## 7. コード品質・保守性

### 良い点

- 型ヒント、dataclass、NumPy ベクトル化、明示的な validation が多く、数値コードとして読みやすい部分が多い。
- Fortran 原典との対応と移植上の意図がコメント・文書に残る。
- 主要式に単体テストがあり、大規模改修時の安全網になる。
- プロジェクト設定、パス、結果出力、GUI が既に相当程度統合されている。

### 改善点

- `pyproject.toml` を追加し、`geosim` を正規パッケージ化する。相対 import または絶対 package import に統一する。
- CLI entry point を設け、カレントディレクトリ依存をなくす。
- 巨大 GUI/パーサーモジュールを、状態モデル、入出力、描画、検証へ分ける。
- `except Exception: pass` や広すぎる fallback を減らす。計算が一部失敗しても続行する場合は、結果ディレクトリへ機械可読の実行ステータスを書き出す。
- Ruff 等の lint、型検査、pytest 化または現在の runner を CI から呼び出す構成を追加する。
- 乱数を使う将来機能では seed とバージョンを結果メタデータへ記録する。

## 8. 文書の整合性

文書量は多いが、現仕様と旧仕様の混在が確認された。

- README は Python モジュール数を 34、テスト数を 604 とする箇所があるが、実際は 45 ファイル、762 テストである。
- `PROGRAM_STRUCTURE.md` は反射履歴の先頭に sentinel `-1` があると説明するが、現実装は sentinel を廃止している。
- 同文書は非 Z 軸 OCS の LWPOLYLINE を未対応とするが、現在のコードとテストは OCS→WCS 変換を含む。
- `loop_deleteredundancy.py` の docstring にも sentinel `-1` の旧説明が残る。
- TODO 冒頭では STI や一部 GUI が完了扱いだが、後半の旧チェックリストでは未実装扱いになっている。
- README と CLAUDE.md のコマンド文字列に U+0008（backspace）が混入し、`docs\build_pdf.py` が環境によって崩れて表示される。

文書は「現行仕様」「既知制限」「履歴/完了済み」を分割し、コードから生成できるファイル数・テスト数を手書きしない方がよい。反射履歴の sentinel のような構造契約の誤記は、将来の実装修正を誤らせるため優先して直すべきである。

## 9. 推奨ロードマップ

5. `NaN`/`Inf`、欠損帯域の validation と warning を整理する。

### 第2段階: 規格と計算定義の固定

3. 分数オクターブフィルタの Class 1 表現を外すか、規格マスク試験を追加する。
4. clarity 指標の時間原点を直接到来時刻へ変更する。
5. coherent の複素反射係数・位相仮定を API と帳票で明記する。

### 第3段階: 妥当性検証

1. 単純矩形室、既知解析解、Fortran 原典を使う end-to-end golden test を固定する。
2. 校正済み実測 IR を持つ 2～3 室で、帯域別 SPL、T20/T30、C80、STI を比較する。
3. 音線数・受音半径・反射次数の収束マトリクスを作る。
4. 吸音率データの測定種別を確定し、変換の要否を材質メタデータへ保持する。

### 第4段階: 配布品質

1. `pyproject.toml`、標準 import、CLI entry point を整備する。
2. Windows を含む CI で compile、lint、全テスト、代表 CLI を実行する。
3. README、構造文書、TODO の旧記述を整理する。
4. 実行ごとにバージョン、入力 hash、規格版、モデル仮定、警告、収束条件を保存する。

## 12. 今回の評価の限界

- GUI を人手で一連操作する受入試験は行っていない。
- 20 万本級の音線を用いる実案件フル計算は行っていない。

- 本報告はコードレビューであり、第三者認証や規格適合証明ではない。

以上を踏まえると、基盤を捨てて作り直す必要はない。現在のテスト資産と機能分割を活かし、まず S1 の計算定義と不具合を修正し、次に実測・外部正解値による妥当性検証へ進むのが最短経路である。
