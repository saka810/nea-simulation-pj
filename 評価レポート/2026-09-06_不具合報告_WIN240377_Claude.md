## ① `inverse_square.py` が「計算済みなのに結果を見つけられない」

**症状**

既定の手順（条件入力の「条件（シート）」を選ばずに計算 → `inverse_square.py`）で、

「先に計算してください」と言われるが、`結果\<室>_まとめ_音圧レベル.csv` は実在する。

**再現手順**

1. `project.json` の `condition_sheet` が空のまま計算する
   （★これは**異常な状態ではなく GUI の既定**。`setup_window._refresh_sheets`
   がコンボボックスの先頭に空欄を置き、選ばなければ空のままにする。

**原因（見立て）**

- **読む側**：`inverse_square.main()` が条件表のシートを全部数え上げ、

## ⑤ `dxf_faces.py` が画層名を壊す（**実案件で踏んだ／実害あり**）

**症状**

REGION の DXF を `dxf_faces.py` で面に直すと、**日本語の画層名が全部文字化けする**。

```
変換後:  ��_1F     �V��{�[�h    ���˔�    �J��_���C
本来:    床_1F     天井ボード    反射板    開口_研修
```

**画層名は吸音材の割り当てに使う**ので、これが崩れると条件表が読めない。
`dxf_faces.py` の決めごとに「★レイヤ名は保つ（吸音材の割り当てに使うので、
これが崩れると意味が無い）」と書いてあるが、日本語では保てていない。

**再現手順**

実案件のモデルで踏んだ。

```
260908_階段教室.dxf（REGION 195 個 / 3DSOLID 7 個・画層 35 種）
python dxf_faces.py "…\260908_階段教室.dxf"
→ 773 三角形 / 画層 20 種。うち日本語の 19 種すべてが文字化け
```

**原因**

`dxf_faces.py:139` が accoreconsole の出力を **UTF-8** として読んでいる。

```python
# geosim/dxf_faces.py:137-139
def _read_dump(path):
    """AutoCAD が書いた辺の一覧を読む。→ (グループ→辺, 落ちたもの)"""
    groups, dropped = {}, []
    with io.open(path, encoding="utf-8", errors="replace") as handle:   # ← ここ
```

accoreconsole は**システムのコードページ（日本語 Windows なら CP932）**で
書き出すので、日本語のバイト列が `errors="replace"` で U+FFFD に置き換わり、
そのまま `_write_dxf`（`:237`、UTF-8 で書く）に渡って**永久に失われる**。

★元の DXF 自体は UTF-8（ヘッダは `$DWGCODEPAGE ANSI_932`）で、
**読み込み側（`read_dxffile`）は正しく日本語を読めている**。
壊れるのは accoreconsole の出力を経由するここだけ。

**★★もっと悪いこと：画層が統合される**

化け方が同じになる画層は**1 つにまとめられてしまい、名前だけでは分離できない**。

| 統合された組 | 面積 |
|---|---|
| `PHP_階段裏` ＋ `PHP_階段下` | 合計 60.08 m² |
| `開口_2F小` ＋ `開口_2F大` | 合計 80.24 m² |

この 4 画層に別々の吸音材を割り当てることは**できない**。

**修正案（未適用）**

CP932 で読んでみて、駄目なら UTF-8 に落とす（逆順でもよいが、
`errors="replace"` は**最後の手段にする**。黙って壊れるのを避けるため）。

```python
def _read_dump_text(path):
    raw = io.open(path, "rb").read()
    for encoding in ("cp932", "utf-8"):     # accoreconsole はシステムのコードページ
        try:
            return raw.decode(encoding)
        except UnicodeDecodeError:
            continue
    return raw.decode("utf-8", errors="replace")
```

`locale.getpreferredencoding(False)` を先に試す形でもよいと思います。

**当座の回避（この端末で実施済み）**

化け方は決定的（`名前.encode('cp932').decode('utf-8','replace')`）なので、
元の DXF の画層名から逆引きして書き戻せる。階段教室では **17 / 19 件**を復元し、
統合された 2 件は `PHP_階段裏＋階段下` / `開口_2F小＋2F大` という名前にした。
復元スクリプトが要るなら出します（`fix/WIN240377_dxf_faces_の文字コード` で
本体の修正案ごと出すこともできます）。

## ⑥ 「条件表を作成」が、選択したプロジェクトフォルダに作られない（**実害あり**）

**症状**

条件入力の「条件表（xlsx）」の欄に**別のフォルダのファイル**が入っていると、
「条件表を作成」を押しても**選択したプロジェクトフォルダには何も作られず、
その別フォルダのファイルが書き換わる**。

**再現手順**（`ct.create()` を直接呼んで確認）

```
① 条件表の欄が空                    → プロジェクト直下に作られる（正しい）
② 欄に前の案件の条件表が残っている  → ★そちらが更新され、
                                       新しいプロジェクトの中身は ['project.json'] のみ
```

**原因**

`condition_table.create()` が `path(project)` ＝ `Project.condition_path` を使う。
`condition_path` は**欄の指定があればそれを返す**ので、別フォルダを指していれば
そこが対象になる。既にファイルがあるので `update()` に回る。

```python
# geosim/condition_table.py:549-555
file_name = path(project)
if not is_book(file_name):
    file_name = os.path.join(os.path.dirname(file_name) or project.folder,
                             CONDITION_BOOK)
if os.path.exists(file_name):
    return update(project, model, library, verbose=verbose)
```

**なぜ実害か**

`update()` は材料番号と安全率は守るが、**面数・面積・参考の式は書き換える**。
つまり**別案件の条件表の面数・面積が、いま開いているモデルの値に置き換わる**。
気づかないまま他案件の入力ファイルが変わってしまう。

**ユーザーの要望（2026-09-06）**

> 条件表の作成は、選択したプロジェクトフォルダ内にしてほしい

**修正案（未適用）**

`create()` は**プロジェクト直下に固定**するのが素直だと思います
（「参照…」で選んだ既存の表を使うのは「読む」ときの話で、「作成」は別）。
あるいは、プロジェクトフォルダを選び直したときに欄をクリアする。

## ⑧ 要望：`dxf_faces.py` が元の図面の POINT（src / rec）を引き継がない

**ユーザーの要望（2026-09-10）**

> POINT も引き継ぎたいですね

**症状**

`dxf_faces.py` は面（閉じた 3D ポリライン / 3DFACE）だけを書き出すので、
**元の図面にあった `POINT` が消える**。音源・受音点は `src` / `rec` 画層の POINT で
渡す決めなので、変換を通したモデルは**毎回、音源も受音点も無い状態から始まる**。

実案件で踏んだ。`260908_階段教室.dxf` には利用者が `Src` 画層に音源 2 点を
置いてくれていたが、変換後のファイルには残らず、`read_dxffile` は
「音源が DXF にありません」と言う。今回はこちらで座標を計算して書き戻した。

**原因**

`_write_dxf()`（`geosim/dxf_faces.py:235-`）が `polygons` しか書かないため。
読み取り側の `_read_dump()` も、AutoCAD に出させているのが**辺の一覧**なので
POINT はそもそも拾っていない。

**あるとよい形（判断はお任せします）**

元の DXF は**そのままテキストとして読める**（ACIS が読めないだけで、
`POINT` のグループコードは普通に取れる。実際にこちらの台本では拾えた）。
accoreconsole を通さず、**元の DXF から `POINT` を直接拾って書き足す**だけで済むと思います。

- 拾う対象は `src` / `rec` 系の画層に限らず、**POINT 全部**でもよいかもしれません
  （`read_dxffile` 側が画層名で選ぶので、余分に入っていても害はない）
- 画層名もそのまま保つ（`Src` / `Rec` の大文字小文字は `_layer_matches` が
  小文字化して見るので問題ない）
- ★同じ考えで、`$INSUNITS` は既に引き継いでいるので、そこに並べる形になると思います

**当座の回避（この端末で実施済み）**

変換後の DXF に `POINT` を書き足す台本を作って使っている。
