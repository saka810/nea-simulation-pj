## 3. 残響時間を ISO 準拠にする（最優先・ユーザー方針）

### 3.1 いま何をしているか

`geosim/reverberation.py:355`

```python
def _decay_time(decay_db, dt, db_start, db_end):
    start = _crossing_index(decay_db, db_start)   # -5 dB を最初に下回る添字
    stop  = _crossing_index(decay_db, db_end)     # -35 dB を最初に下回る添字
    return (stop - start) * dt * 60.0 / (db_start - db_end)
```

**減衰曲線の 2 点しか見ていない。** ISO 3382-1 が求めているのは
「評価区間（T30 なら −5〜−35 dB、T20 なら −5〜−25 dB、EDT なら 0〜−10 dB）の
**減衰曲線に直線を最小二乗で当て**、その傾きから 60 dB 減衰時間を外挿する」
であり、2 点法とは別物である。

### 3.2 実際にどれだけ違うか（`test.dxf` の end-to-end で確認）

2×3×1 m の箱・音線 20,000 本・反射 25 回・受音球 0.2 m で回し、
できたインパルス応答の減衰曲線を 2 通りで読み直した。

| Hz | 2 点法 T30 | **回帰 T30** | 差 | 2 点法 T20 | 回帰 T20 | **ξ=1000(1−r²)** | **ISO の C** | 実装の曲率 |
|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| 63 | 0.1377 | 0.1310 | −4.9% | 0.0716 | 0.0694 | **178.6** | +92.5% | +85.9% |
| 125 | 0.1352 | **0.1835** | **+35.7%** | 0.0816 | 0.0781 | **160.5** | +65.8% | +97.2% |
| 250 | 0.1634 | 0.1647 | +0.9% | 0.1607 | 0.1438 | 19.7 | +1.7% | +5.6% |
| 500 | 0.1507 | 0.1470 | −2.4% | 0.1416 | 0.1425 | 9.0 | +6.4% | +0.9% |
| 1000 | 0.1576 | 0.1483 | −5.9% | 0.1395 | 0.1299 | 12.6 | +13.0% | +20.9% |
| 2000 | 0.1311 | 0.1199 | −8.5% | 0.1305 | 0.1285 | 6.9 | **+0.4%** | **−11.8%** |
| 4000 | 0.1060 | 0.1101 | +3.9% | 0.1029 | 0.1117 | 3.1 | +3.0% | +2.3% |
| 8000 | 0.0807 | 0.0724 | −10.3% | 0.0761 | 0.0738 | 10.2 | +6.1% | −1.5% |

読み取れること。

- **減衰がまっすぐなときは 2 点法でもほぼ合う**。理想的な指数減衰を合成して試すと
  2 点法と回帰の差は 1% 未満だった。だから「いままでの数字が全部でたらめ」ではない。
- **減衰が曲がっているところで大きくずれる**。125 Hz で **35.7%**。
  幾何音響で扱う実室（平行面・面ごとに吸音が違う・非拡散）では
  減衰は普通に曲がるので、これは例外ではなく通常条件である。
- **2000 Hz を見ると、いまの曲率は当てにならない**。ISO の C が +0.4%（＝まっすぐ）
  なのに実装の曲率は −11.8% で「★信用しないこと」の警告が出る。**偽警報**である。
- **回帰にすると ξ（非線形性）が無料で手に入る**。63・125 Hz の ξ が 178・160 で、
  ISO 3382-2 の目安（ξ ≦ 10 程度）を桁で超えている＝この 2 バンドは
  **どんな読み方をしても信用してはいけない**、と数値で言い切れるようになる。
  いまは曲率の符号を見て人間が判断するしかない。

### 3.3 直すべきものは 3 つある

**(a) 読み取りを最小二乗回帰にする**（`_decay_time`）

```python
def _decay_time(decay_db, dt, db_start, db_end, detail=False):
    """ISO 3382 の読み取り。評価区間へ直線を最小二乗で当て、60 dB へ外挿する。"""
    start = _crossing_index(decay_db, db_start)
    stop = _crossing_index(decay_db, db_end)
    if start < 0 or stop < 0 or stop <= start:
        return (np.nan, None) if detail else np.nan
    t = np.arange(start, stop + 1) * dt
    y = decay_db[start:stop + 1]
    slope, intercept = np.polyfit(t, y, 1)
    if slope >= 0.0:                      # 減衰していない（適合不良）
        return (np.nan, None) if detail else np.nan
    value = -60.0 / slope
    r = float(np.corrcoef(t, y)[0, 1])
    info = {"slope_db_per_s": float(slope), "intercept_db": float(intercept),
            "r2": r ** 2, "xi": 1000.0 * (1.0 - r ** 2),
            "range_db": (db_start, db_end),
            "range_s": (float(t[0]), float(t[-1])), "samples": len(t)}
    return (value, info) if detail else value
```

★**2 点法は消さずに `method="crossing"` として残す**こと。
このリポジトリの流儀（scalar 版・厳密版を参照実装として残す）に合っているし、
元 Fortran（`ipls2rt_fortran.f90` 134 行）との一致確認にも要る。

**(b) 曲率 C を ISO の定義に直す**

```python
# 現状: half = _decay_time(decay, dt, -5, -20)     ← -5〜-20 dB。ISO の C ではない
# 修正: t20  = _decay_time(decay, dt, -5, -25)
#       t30  = _decay_time(decay, dt, -5, -35)
#       C    = (t30 / t20 - 1.0) * 100.0
```

`decay_measures` は既に T20 と T30 を両方作っているので、
**曲率はそこから出せばよく、専用に 1 本追加で回す必要はない**。
`decay_curves` 側の曲率は `decay_measures` から受け取る形に寄せるのが素直。

**(c) 適合の質を出力に載せる**

回帰にすると `r²` / `ξ` / 実際に使った区間（dB と秒）/ 傾き が手に入る。
`残響時間.csv` に**区分「適合」**として並べるのがこのリポジトリの表の流儀に合う
（`table.write_sectioned_table` の区分付き表）。
判定はメッセージではなく数値で残す。

### 3.4 同時に検討したい 2 点（優先度は下）

- **応答長の余裕を確かめる**。ISO 3382 は評価区間の下端よりさらに 10 dB 下まで
  減衰が見えていることを求める（T30 なら −45 dB）。シミュレーションでは暗騒音は無いが、
  **反射回数の打ち切り**と**インパルス応答長の打ち切り**が同じ役目の「床」を作る。
  `nref` の警告（`procedure.py:384`）は既にあるので、そこへ
  「減衰曲線が −45 dB に達しているか」の判定を足せば揃う。
- **逆方向フィルタ**。IEC 61260 の因果 IIR は自分自身の立ち上がりを持つので、
  時間反転した応答をフィルタして戻す方法が推奨される。
  ただし今回の数値実験では、順方向と逆方向の差は**BT 積由来のばらつきに埋もれる**
  （63 Hz・T=0.5 s で 0.524 s 対 0.539 s）。**急ぐ話ではない**。

### 4.1 明瞭度の起点（Codex が S2 としたが、ISO 準拠の観点では S1）

`reverberation.py:544` は各バンドで `int(np.argmax(energy))` を直接音の到来時刻とする。
ISO 3382-1 が求めているのは「**ピークより 20 dB 低いレベルを最初に超える点**」である。

これは「強い初期反射があると起点がずれる」（Codex の指摘）だけの話ではない。
**帯域フィルタを通すと直接音のパルスが時間的に広がる**ので、低域では
`argmax` が真の立ち上がりより**あとに**来る。63 Hz のバンドではフィルタの
インパルス応答自体が数十 ms に及ぶので、50 ms の窓が構造的にずれる。
つまり**低域の C50 / D50 は系統的に大きく出る**。

残響時間を ISO 準拠に直すなら、**起点の規定も同じ回で直すのが筋**である
（どちらも ISO 3382-1 の同じ「減衰曲線の作り方」の話）。

## 5. Codex の評価を補正すべきところ

### 5.1 空気吸収は「ISO 9613-1 型」ではなく「ISO 9613-1 そのもの」

規格式（酸素・窒素の緩和周波数、飽和水蒸気圧の 10^(−6.8346(T01/T)^1.261+4.6151) を含む）を
独立に書き起こして比較した。

| 条件 | 63 | 125 | 250 | 500 | 1k | 2k | 4k | 8k |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| 20℃ 50% 実装 [dB/km] | 0.122 | 0.440 | 1.310 | 2.728 | 4.665 | 9.887 | 29.666 | 105.291 |
| 20℃ 50% 規格式 | 0.122 | 0.440 | 1.310 | 2.728 | 4.665 | 9.887 | 29.666 | 105.291 |
| **比** | **1.0000** | 1.0000 | 1.0000 | 1.0000 | 1.0000 | 1.0000 | 1.0000 | 1.0000 |

20℃70%、15℃60% でも同じく全バンド比 1.0000。
**ここは「準拠」と書いてよい**（気圧の単位が kPa である点だけ、API の注意書きが要る）。

音速 344.19 m/s・ρc = 411.9（20℃70%）も湿り空気として妥当。

### 5.2 IEC 61260 は「主張を弱める」だけでなく「合っている部分は認める」

Codex は「クラス 1 の主張を外せ」とだけ言っているが、実装を見ると
**中心周波数（呼び値）・帯域端（1/1 は f/√2〜f√2、1/3 は f·2^(∓1/6)）は規格どおり**で、
1/3 の呼び中心周波数表も IEC 61260 / JIS C 1513 と一致している。

書き換えるべきなのは 1 行だけである。

- 現在：「IEC 61260 準拠の Butterworth」「クラス 1 オクターブフィルタに相当する次数」
- 提案：「**IEC 61260 の中心周波数・帯域端に基づく 6 次 Butterworth バンドパス。
  規格の減衰量マスクへの適合試験は行っていないため、クラスの表示はしない**」

### 5.3 受音球は S1 ではなく S2

外れるのは「受音球の中心が、その音線区間の終点（壁）より先にある」場合だけである。
つまり**受音点が壁から受音球半径以内にあるとき**に限られる。
半無響室の測線のように壁から離れた受音点では起きない。直すべきだが、
「公開前に必ず」の枠は残響時間・空気吸収・coherent に絞ったほうが判断しやすい。

なお修正するなら、Codex が挙げた clamp に加えて
**始点が球の内側にある場合**（`inner_product < 0` でも区間が球と交わる）も
同時に拾えるようになる。いまは `inner_product >= 0` で切っている。

## 7. 良いところ（残すべき設計）

評価の対称性のために明記しておく。

- **音線は「経路を見つける網」で、エネルギーは虚音源から `1/(4πd²)` で出す**。
  この分業のおかげで、音線法で普通に問題になる**受音球の断面積による正規化バイアスが原理的に無い**。
  受音球半径は精度のつまみであってエネルギーの係数ではない。設計として正しい。
- **反射率 R(θ) = (z cosθ−1)/(z cosθ+1)** が `sound_ray.energy_decay` と
  `absorption.impedance_from_normal` で**同じ z の定義**で書かれており、二重管理になっていない。
- **参照実装を消さない流儀**（scalar 版の交差判定、厳密版の伝達関数、`backtrace_path`）。
  高速化のたびに一致をテストで押さえているのは、この種のコードでは珍しく良い。
- **経路キャッシュに指紋を持たせ、吸音率の値は指紋に入れない**。
  「何が結果を変えるか」を理解して線を引いている。
- **`nref` 不足の警告がエネルギーで判定される**（`procedure.py:384`）。
  「反射回数に達した経路がある」だけでは警告にしない、という切り分けが正しい。
- **窓付き sinc による端数遅延**。「サンプル時刻へ寄せる」やり方との違いを
  干渉の谷の周波数で実測して確かめてある（5937.8 Hz 一致 / 寄せると 5512.5 Hz）。
- 762 テスト全通過（UTF-8 モード）。CP932 では `≈` で落ちるのは Codex の指摘どおり。

## 8. 優先順位（私の提案）

Codex のロードマップとおおむね同じだが、**順番を変える**。
ユーザーの方針（ISO 準拠の残響時間）と、費用対効果で並べ直した。

### 第 1 段（ISO 3382 まわり。ひとまとまりで直す）

1. `_decay_time` を最小二乗回帰にする（2 点法は `method="crossing"` で残す）
2. 曲率 C を `(T30/T20−1)×100` に直す
3. `ξ = 1000(1−r²)`・使用区間・傾きを出力に足す（区分付きの表）
4. 明瞭度の起点をピーク −20 dB にする
5. 減衰が −45 dB（T30）まで見えているかの判定を `nref` 警告に合流させる
6. テスト追加：指数減衰（回帰＝解析解）／二重勾配／打ち切りあり／2 点法との一致条件
7. 文書 4 か所とテストと PDF を同じコミットで更新

### 第 2 段（結果を誤らせる不具合）

8. `frequency_response.response()` の空気吸収を実装する
9. coherent の帯域別 PWL を保持し、`overall` / A 特性 / 内訳も同じ計算法で出し直す
10. 受音球を有限線分 × 球の判定にする（始点内包も拾う）
11. `modal_frequencies` の次数を寸法と上限周波数から決める
12. `Atmosphere` の気圧の単位を検査・明記する

### 第 3 段（規格表示の固定）

13. STI の版を `IEC 60268-16:2011` と明記し、条件と帳票に記録する
    （2020 年版へ寄せるかは別途判断。女声 STI を落とすことになる）
14. IEC 61260 の「クラス 1」表示を外す（マスク試験を通すまで）
15. 帳票に「幾何音響・鏡面反射モデル／未考慮：散乱・回折・透過・反射位相・音源指向性」を記録

### 第 4 段（検証・配布）

16. 吸音率データの素性を確定（α か |R| か。9/4 の宿題）
17. 音線数・受音球半径・反射回数の収束表
18. 外部正解値または実測との突き合わせ

## 9. この評価の限界

- GUI の受入試験はしていない。
- 実案件（半無響室・階段教室）のフル計算はしていない。数値の裏取りは `test.dxf`
  （2×3×1 m）と合成信号で行った。**小さい室は BT 積が小さく、
  残響時間のばらつきが出やすい条件である**ことは割り引いて読む必要がある。
- 規格本文は手元に無い。ISO 9613-1 は式を独立に書き起こして数値照合したが、
  ISO 3382 / IEC 60268-16 / IEC 61260 については**条項番号まで確かめていない**。
  実装を直す前に規格本文で該当条項を確認することを勧める。
- 実測データが無いので、現実の室に対する精度は評価していない。
